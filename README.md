Research and future native Nintendo Switch remake of The Story of Thor 2 / The Legend of Oasis for Sega Saturn.

**Status: Stage 62 host sandbox plus Stage 66–101 static SH-2/VDP1 research — the original-asset-free C++17 gameplay sandbox remains synthetic and is not a playable Nintendo Switch NRO. Stage71–72 verify the static callback registration and signed-status handshake. Stage73 traces the callback's signed-word length formula and special transfer path. Stage74 verifies a static D0EN write of `0x0101`, audits three transfer handlers, and records nine count-increment sites guarded by limits 508 or 460; two other increments follow local zero resets and one additional pattern remains unclassified. Stage75 traces both callback length-field assignments to the same global source word. One source writer has a zero-seeded R10 path; the other copies the current length/count word through R13. Stage76's direct SH-2 CFG walk, anchored at the complete routine prologue, confirms these facts along intraprocedural paths. Stage77 resolves the three direct BSR targets and one nested literal-backed indirect call; the five-function graph preserves R10/R13, including the wrapper's R13 save/restore paths. Stage78 finds two literal-backed indirect JSR call sites to the writer routine and two direct word store candidates in a bounded alias audit, with no additional ADD-immediate alias store candidates. An RTS separates one nearby call site from the submit gate, so physical code proximity does not imply runtime ordering. Stage79 expanded the local ISO audit across direct, predecrement, indexed, and displacement store modes: 24 nearby PC-literal candidates produced the same two direct MOV.W writer candidates, with no new additive aliases or unresolved indexed candidates in the bounded windows. This does not exhaust arbitrary dynamic aliases. Stage80's direct CFG walk visits 707 states in the writer routine: both known source-field stores are reached, and the observed RTS and tail-BRA exits occur after a store. Both literal-backed writer callsites are followed directly by callback ID 64 without an intervening branch. This proves only the analyzed static paths. Stage81 identifies four literal-backed callback ID 64 JSR sites: two follow a writer call, while two copy the source word into the length field in the callback delay slot without an immediately preceding writer call. All four match these known patterns, but table/computed targets and initialization before the two copy reads remain unproven; the global length bound also remains open. Runtime callback invocation, DMA completion and same-frame timing are not claimed. Stage91 finds a guarded static path that loads SET07.BIN and then performs JSR through the same destination buffer. Stage92 corrects CFG reachability to execute delay slots, decodes the entry predicates (global word == 0x60, a local snapshot reloaded into R5 == 6, and a 16-bit word loaded through R14 into R4 == 15), and confirms there is no explicit loader-status check before the entry call. Stage93 traces the shared loader wrapper: two internal helper calls each have a nonnegative-result check, negative paths call a common error helper with codes 1 and 2, and the wrapper returns the second result. The SET07 caller still does not check that result; its startup code contains a mask-0x40 polling loop, not confirmed callback registration. Stage94 finds that both negative loader paths call a common error helper whose final JSR returns into a pointer table with no local RTS/RTE; this strongly suggests non-returning behavior but does not prove it at runtime. Therefore, continuation after a negative result is conditional on the error helper returning. Stage95 finds 13 literal-backed candidates for a shared dispatch slot across 0TH2.BIN, TH2.LOW and SET07.BIN, with 10 recognized indirect call sites and no bounded local store candidates; the slot's initializer and callback semantics remain unresolved. Stage96 widens the writer scan to pointer literals within 0x80 bytes and 128-instruction windows across 30 root payloads: zero resolved store candidates, with one unresolved indexed-byte-store candidate in MONS.BIN because R0 is unknown; that file has zero matches for the generic stack-prologue signature, so the candidate is likely a data false positive and is not counted as a writer. Three large CPK containers remain outside the full code scan. Stage97 anchors the error-helper CFG at the shared negative-path BSR from the recognized loader wrapper. Both optional-target literal references in 0TH2.BIN are reachable on bounded delay-aware CFG paths and each is immediately followed by JSR @R0. Both map inside the unique candidate TH2.LOW load range; target 1 matches the full generic prologue signature, while target 2 matches only the weaker legacy entry shape. Stage98 finds two exact-address byte-store candidates for the error-helper control byte in 0TH2.BIN. Both are reachable only as call delay slots from a boot-reachable literal-backed caller anchor. The first stores zero; the second uses R13, seeded to one before three calls and a conditional branch, so its final value remains unproven. Static reachability does not prove runtime invocation or target semantics. Stage99 audits the three calls before the second control-byte store: one local BSR preserves R13 via save/restore, the loader-wrapper normal-success path preserves it through both helpers, and the first callee has an unresolved indirect call through a low-memory pointer slot. No store to that slot was found in 30 fully scanned root payloads. The second store is in the delay slot of a later BSR, so that callee starts after the store. Value 1 is conditional on the unresolved service call preserving R13 and the wrapper returning normally. Stage100 finds the same low-memory service-slot pattern in boot/system-area code, 0TH2.BIN and SET07.BIN: 10 exact literal references in root payloads and ten pointer-dereference JSR patterns, plus one boot-area call pattern. No bounded store candidate was found in the 30 scanned payloads or boot-code window. The Renesas SH calling-convention note supports the expectation that R13 is callee-saved for ABI-conforming functions, but the slot's actual runtime target remains unresolved. Stage101 targeted all three oversized CPK payloads for exact service-slot pointer bytes and aligned PC-relative MOV.L literals: zero matches in 96,244,268 bytes. This is not a full disassembly and does not prove runtime initialization or target identity. The original ISO and executable remain private; no runtime VDP1 capture is claimed.**

Stage 46 — verified one SH-2 submit gate supplying the Stage45 32-byte VRAM command copier. Stage66 statically cross-checked the descriptor consumer: each 8-byte record contains a 32-bit source address, an unsigned 16-bit VDP1 destination slot scaled by 8, and a signed 16-bit block count used for 32-byte transfers. The count must be positive for finite completion; zero/negative values are not empty transfers in the original do-while loop. The portable parser and tests use synthetic data only. Stage70 additionally finds a status-writer callback registration candidate under ID 64 and a pointer-derived PTMR=2 write; neither static finding proves runtime execution. Actual VDP1 execution and producer/submit same-frame timing remain unproven. This repository contains research tools, not a playable game.

## Verified progress

- **Stage 01:** verified Saturn MK-81302 ISO9660 structure with 33 files.
- **Stage 02:** identified 12 candidate three-section containers.
- **Stage 03:** validated 21 counted big-endian 16-bit index tables and nine six-byte record chains.
- **Stage 04:** validated 3,730 records across ten containers using the 6 + 8×N grammar; MONS.BIN and P4.BIN need separate handling.
- **Stage 05–06:** profiled candidate fields and compared byte offsets with the ×8 address hypothesis.
- **Stage 07:** found strong 32-byte texture-address alignment and candidate lists pointing to 14-byte records ending in 0x7FFF; record semantics remain unproven.
- **Stage 08:** added a local PNG previewer for 4/8/16bpp assumptions. Candidate dimensions and palette remain unknown.
- **Stage 09:** analyzed 13,574 candidate blocks; the median fraction of bytes with identical high/low nibbles is 68.23%, consistent with packed 4bpp or another nibble-structured encoding, not proof of raw 4bpp.
- **Stage 10:** confirmed that block lengths admit many dimension/format combinations and a broad RGB555-like scan produces too many palette candidates.
- **Stage 11:** characterized MONS.BIN and P4.BIN separately. Both have counted index tables, but their record headers mostly fail the Stage 04 counter rule.
- **Stage 12:** found exact Saturn VDP1/VDP2 address literals in 0TH2.BIN and some other files; literal presence alone does not prove executable code.
- **Stage 13:** found 46 candidate SH-2 MOV.L PC-relative references to known graphics-hardware constants, using 38 unique literal slots; code/data boundaries remain unverified.
- **Stage 14:** identified one exact SH-2 signature that copies eight longwords (32 bytes) per iteration to VDP1 VRAM. Two additional instruction sequences independently compute VDP1_BASE + index*8.
- **Stage 15:** resolved a PC-relative function-pointer literal to an indirect JSR call site; inferred an 8-byte descriptor (4-byte source address, 2-byte destination index, 2-byte per-source record count). The caller passes the staging buffer in R4 and a global total-copy budget in R5, guarded against zero and cleared after the call.
- **Stage 16:** identified a candidate descriptor writer with a 512-entry capacity guard, stores at descriptor offsets 0/4/6, one global-counter increment per descriptor, and an 8-byte pointer advance. The per-source count is input >> 3, so callers must be traced to validate how this agrees with the uploader's per-copy budget.
- **Stage 17:** found no direct BSR or PC-relative absolute writer-address literals targeting the capacity guard. That does not imply the writer is unused.
- **Stage 18:** verified a capacity BT branch and an earlier BF/S branch converging just after the 8-byte descriptor commit, demonstrating a conditionally executed writer block rather than a proven standalone routine entry.
- **Stage 19:** validated CMP/EQ #1,R0, BF/S with EXTU.W R5,R4 in its delay slot and three SHLR R2 before the count store. This derives the local count formula (R5 & 0xFFFF) >> 3. Runtime R5 values and the global copy-budget accounting remain unresolved.
- **Stage 20:** resolved the preceding EXTU.B R5,R5; EXTU.B R3,R3; MULU.W R3,R5; STS MACL,R5 chain. The per-source count follows (unsigned_byte_factor_A * unsigned_byte_factor_B) >> 3, gated by a stack byte at SP+80 equal to 1 and the capacity guard.
- **Stage 21:** located both unsigned-byte factor loads at SP+20 and SP+32, and the writer-enable flag at SP+80. The original provenance and runtime contents of these stack fields remain unknown.
- **Stage 22:** recognizes an 88-byte stack frame after seven saved registers and 18 narrow direct SP stores before the factor loads. Two stores cover the SP+80 flag; none of the strictly recognized stores cover SP+20/SP+32.
- **Stage 23:** finds four pointer-mediated writes through temporary aliases of R15: two to SP+20, one to SP+32, and one to SP+56. Their candidate value sources include byte fields R4+2, R4+3, R4+1 and a separate conditional rewrite masking SP+20 with 0x3F.
- **Stage 24:** verifies one complete loop structure linking R4+1 to a byte counter at SP+56; after each pass it is decremented and checked as signed, with a backward BRA to the loop head and a NOP delay slot. A pure counter model is tested, not a measured game iteration count.
- **Stage 25:** confirms one function prologue saving the entry R4 pointer in R13 and a later BSR passing R13 back through R4 in its delay slot. One branch-free loop prefix leads to an AND 0x3F rewrite of SP+20.
- **Stage 26:** proves the Stage25 helper copies incoming R4 to R14, reads a 32-bit field at memory[R14+160] into R4 before its first conditional branch, tests for null, then restores PR/R12/R13/R14, but not R4, in its matched return.

- **Stage 28:** validates the nonzero arm writing the same fields from nested data: byte order of +31/+32 reverses when the signed type byte is 3, source values for +35 and +36 are shifted left, and two conversion groups of 2 and 4 JSR @R13 calls are skipped separately when 16-bit fields +88/+90 equal 0x0100.

The second reader gates field access on bit0 of R4+7 being clear; the first tests bit2 of R4+6 earlier, and the extended reader has no recognized branch in its initial prefix.
