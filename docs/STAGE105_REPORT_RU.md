# The Story of Thor 2 — Stage 105: проверка сохранённых aggregate evidence

## Правило хранения

Работа ведётся по стандарту Project Evidence Archive. Приватные оригиналы остаются в Google Drive: `01_Private_Originals`. Неизменённые захваты и логи — в `02_Raw_Traces_and_Captures`; aggregate JSON — в `03_Aggregate_Reports`; манифесты с SHA-256, размерами и source commit — в `00_Manifest_and_SHA256`; CI-данные — в `04_Logs_and_CI`; stage handoff — в `05_Handoff_and_Stage_Notes`.

Публичный GitHub содержит только код, синтетические тесты и безопасную документацию. Образ Saturn, извлечённые ресурсы, трассы, RAM-адреса, смещения инструкций и сырые байты кода в GitHub не помещаются.

## Аудит архива

Проверена каноническая приватная папка проекта The Story of Thor 2 в Project Evidence Archive. В `03_Aggregate_Reports` есть приватные человекочитаемые отчёты Stage 99–104, однако отдельные точные JSON-файлы вывода анализаторов Stage 99 и Stage 103 там не обнаружены. В `00_Manifest_and_SHA256` есть текстовые манифесты соответствующих этапов, но по ним нельзя реконструировать первоначальные JSON без повтора анализа.

Следовательно, **Stage 104 gate ещё не был проверен на двух сохранённых исходных aggregate JSON**. Нельзя заменять отсутствующие JSON текстовыми сводками или синтетическими fixture.

## Реализация Stage 105

Добавлен `tools/stage105_evidence_archive_input_integrity.py`, который принимает ровно два JSON и манифест с SHA-256, размером исходного ISO, размером каждого aggregate JSON и полными SHA commit их генераторов. Перед запуском evidence gate проверяются hash/size, имена stage, schema, явная отметка об отсутствии private-address payload и запретные сырьевые поля. При любой ошибке gate не исполняется, а CLI возвращает код 2. Программа не читает ISO и не раскрывает JSON исходных отчётов.

Добавлено пять синтетических регрессионных тестов: успешный условный вывод без runtime claim; изменение байта; чужой stage; потерянный source commit; приватный raw-field. GitHub Actions необходим для утверждения, что тесты выполнены в CI.

## Следующее действие

1. Повторно запустить анализаторы Stage 99 и Stage 103 на **неизменённом приватном ISO** (источник: 106 954 752 байта; закреплённый SHA-256: `25b0b2774d4621bd9f95a01fc5420ded37b481b61b3cdf515360d82b2cb7bb0d`), сохранив точные сырые результирующие aggregate JSON без переписывания полей.
2. Вычислить SHA-256 обоих JSON и записать исходный commit каждого анализатора, размер и исходную ISO identity в отдельный манифест.
3. Загрузить JSON в `03_Aggregate_Reports`, манифест — в `00_Manifest_and_SHA256`, подтвердить сохранение и свойства каждого файла через readback в Drive.
4. Локально запустить Stage 105 gate на этих сохранённых файлах. Сохранить его sanitized output как новый артефакт и дополнить `05_Handoff_and_Stage_Notes`.
5. До выполнения шагов 1–4 статус условного результата Stage 104 не повышать до «проверен на реальных сохранённых данных».

**Граница доказательства:** интерфейс `SYS_CHGSCUIM` и стандартный SHC ABI поддерживают условное сохранение `R13`, но сам runtime-slot, конкретная BIOS реализация и безусловное значение второго writer не подтверждены.
