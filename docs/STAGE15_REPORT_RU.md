# The Story of Thor 2 — Stage 15: найден вызов VDP1-загрузчика

Дата: 21.10.2026. Анализ выполнен локально на приватном ISO Sega Saturn MK-81302. В репозиторий добавлены только анализатор, синтетические тесты и агрегированные выводы; исходный образ и игровые ресурсы не публикуются.

## 1. Связь функции с вызывающим кодом

В 0TH2.BIN найден PC-relative литерал, значение которого совпадает с адресом найденной на Stage 14 функции. Следом обнаружен косвенный вызов JSR @R2. Это подтверждает статическую связь между функцией копирования и конкретным путём вызова внутри исполняемого файла.

| Проверка | Результат |
|---|---:|
| Совпадений сигнатуры функции | 1 |
| Ссылок на адрес функции с последующим косвенным вызовом | 1 |
| Прямых относительных BSR к функции | 0 |
| Ссылок на указатель staging-буфера | 2 |
| Ссылок на общий счётчик записей | 7 |

База загрузки 0x06004000 выведена из адреса функции в литерале и совпадения с найденной сигнатурой. Это статический вывод, а не подтверждение исполнения в эмуляторе.

## 2. Что передаёт вызывающая сторона

Перед вызовом код загружает адрес staging-буфера в R4. Отдельно считывается 16-битный общий бюджет копирования в R5; перед вызовом есть проверка на ноль. После возврата общий счётчик очищается, а сохранённый указатель буфера восстанавливается.

Важно: R5 — не количество дескрипторов. В теле найденной функции R5 уменьшается на каждом скопированном 32-байтовом блоке. Поэтому это общий бюджет оставшихся записей копирования. Поле R2 внутри каждого дескриптора задаёт число записей для текущего источника.

## 3. Предварительно восстановленная структура дескриптора

Из последовательности чтения и использования полей получена структура размером 8 байт:

| Поле | Размер | Использование |
|---|---:|---|
| Адрес источника | 4 байта | Чтение 32-байтовых записей |
| Индекс назначения | 2 байта | Умножается на 8 и прибавляется к базе VRAM VDP1 |
| Количество записей для источника | 2 байта | Ограничивает внутренний цикл копирования |

Каждая копируемая запись занимает 32 байта; назначение вычисляется как VDP1_VRAM_BASE + destination_index × 8.

Эта структура подтверждается последовательностью инструкций, но фактическое содержимое staging-буфера ещё не декодировано. Его адрес относится к рабочей памяти во время исполнения, и статический файл не доказывает, какие именно значения в него записываются.

## 5. Следующий этап

Stage 16 — найти код, который заполняет staging-буфер: проследить обращения к сохранённому указателю, найти запись 8-байтовых дескрипторов и связать поля адреса источника с ресурсами P0–P3. Только после этого можно достоверно сопоставить дескрипторы с конкретными спрайтами и текстурами.

Статус: найден статический путь косвенного вызова VDP1-загрузчика и восстановлена предварительная структура дескриптора. Runtime-прохождение, фактическое содержимое буфера, декодер текстур, игровой движок и Switch NRO ещё не созданы.
