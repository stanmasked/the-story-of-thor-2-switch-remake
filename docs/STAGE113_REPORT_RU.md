# The Story of Thor 2 — Stage 113: свидетельство фактически диспетчеризуемых инструкций SH-2

## Исходные ограничения

Stage112 подтвердил на двух идентичных, но независимо выполненных двухмиллионных трассах наличие изменений R13 и PR, одно изменение целевого RAM-байта и один контекстный кандидат RPC==PR. Эти события относятся к длинному интервалу исполнения. Они не показывают, какая конкретная инструкция вызвала изменение RAM, и не доказывают возврат из вызываемой процедуры. Поля PC_ID, PC_IF и RPC сами по себе не являются адресом однозначно выполняемой инструкции.

## Новый инструмент

stage113_patch_mednafen_opcode_trace.py добавляет в публичный Mednafen 1.29.0 ещё один наблюдатель, выключенный по умолчанию. Он ставится на уровне SH7095::Step, где эмулятор выбирает и исполняет обработчик из Pipe_ID. Для каждого наблюдаемого шага в приватный журнал записываются pre/post-состояния pipeline и регистров, полный Pipe_ID, 16-битное слово инструкции и идентификатор диспетчеризации. Строка post записывается только после обычного завершения обработчика и продвижения шага. Если выполнение уходит по пути с ранним возвратом и пара не закрывается, строгий gate отклонит трассу.

Триггер, путь вывода и лимит передаются только переменными среды при приватном запуске. Лимит ограничен 8192 шагами на каждый затронутый CPU. В исходнике нет адресов игры, ISO, BIOS или трасс. Наблюдатель не читает MMIO и не изменяет состояние CPU.

stage113_opcode_trace_gate.py проверяет заголовок, формат, последовательность шагов, соответствие Pipe_ID слову инструкции, пары pre/post и целостность диспетчеризованной инструкции. Он выводит только агрегированные счётчики для RTS, BSR, JSR, BSRF, RTE, изменений R13/PR и неполноты захвата. Даже обнаружение завершённой диспетчеризации RTS или последовательности BSR→RTS с совпадающим PR обозначается только как кандидат; полное доказательство возврата остаётся выключенным до отдельной проверки адреса возврата, delay slot и контекста вызова.

## CI и воспроизводимость

Отдельный публичный workflow сначала запускает только синтетические тесты, затем восстанавливает открытый исходник Mednafen, применяет Stage109/111/112/113 и компилирует публичный бинарник вместе с совместимой библиотекой FLAC. Оригинальная игра, BIOS, приватные адреса и сырые трассы не передаются в CI. После успешной сборки архив и SHA-256-манифест будут сохранены в приватном Project Evidence Archive.

## Критерий завершения Stage113

1. Все синтетические тесты gate и патчера проходят.
2. GitHub Actions собирает точный источник с новым наблюдателем.
3. Два приватных запуска оригинальной игры выполняются на проверенных SHA-256 ISO/BIOS.
4. Сырые opcode-трассы и их SHA-256 сохраняются и повторно проверяются в owner-only Google Drive.
5. Отдельный приватный анализ сопоставляет диспетчеризованные opcode с изменением целевого байта и проверяет, наблюдались ли BSR, фактически завершённый RTS и совпадающий адрес возврата.

До получения пунктов 2–5 это только подготовленный эксперимент, не новое динамическое доказательство. Stage104 остаётся условным.
