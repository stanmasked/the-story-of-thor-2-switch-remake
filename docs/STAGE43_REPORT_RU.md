# The Story of Thor 2 — Stage 43: приватные точки остановки и проверка снимков SH-2

Дата: 22.10.2026. Исходный Sega Saturn ISO MK-81302 проверен локально; SHA-256 `25b0b2774d4621bd9f95a01fc5420ded37b481b61b3cdf515360d82b2cb7bb0d`. **Оригинальный ISO, адреса его исполняемого кода, память игры и сырой журнал исполнения не включены в GitHub.**

## Цель

Stage 42 нашёл два пролога индексированной диспетчеризации через таблицу 68 функций, но не доказал, что их входной R4 совпадает с новым 276-байтным объектом из пула Stage 40. Stage 43 позволяет исследовать эту связь по реальным регистрам и точкам исполнения вместо совпадений полей.

Локальный запуск Stage 43 на оригинальном ISO успешно вычислил **семь ролей точек остановки**:

1. Состояние `R0` после возврата процедуры поиска свободного слота (`slot-return`).
2. Вход в функцию копирования, на котором `R4` — источник, `R5` — назначение (`copy-entry`).
3. Инструкция записи индекса 38, где `R14` — выбранная запись, а `R3` — записываемая константа (`index-store-pre`).
4. Вход первой диспетчеризации, от начала 68-элементной таблицы (`dispatch-entry`, `table_start`).
5. Её косвенный `JMP` с адресом цели в `R3` (`dispatch-jmp-pre`).
6. Вход второй диспетчеризации, относительно ячейки №39 (`dispatch-entry`, `selected_cell`).
7. Её косвенный `JMP` с адресом цели в `R2` (`dispatch-jmp-pre`).

Адрес выбранного слота вычисляется от приватного начала пула по формуле `pool_base + slot × 276`, слот целочисленный в диапазоне 0…42. Для проверки последовательности сравниваются **одни и те же физические адреса** (а не пользовательский символьный идентификатор) при выделении, копировании, записи индекса и входе в обработчик.

## Почему два пути к функции №39 различаются

Stage 36 подтвердил две адресации таблицы:

- От начала таблицы: сохранённый в объекте индекс **38** адресует функцию №39.
- От самой ячейки №39: необходим относительный индекс **0**, а не 38.

Поэтому прежнюю символьную последовательность Stage 42 нельзя считать достаточной, если она показывает запись 38 и немедленную диспетчеризацию от ячейки №39 с индексом 0 **без промежуточной записи нового значения в память того же объекта**. Анализатор Stage 43 допускает вторую ветку лишь при отдельном снимке 16-битной записи `38→0` по адресу `slot_pointer+126`. Это тоже лишь внутренне согласованный журнал; его происхождение ещё требуется подтвердить.

## Локальное воспроизведение

После установки в приватной среде Sega Saturn-эмулятора с SH-2-отладчиком:

```bash
python tools/stage43_private_watchpoints.py "/private/The Story of Thor 2.iso" \
  --manifest-private /private/thor43.private-watchpoints.json \
  --summary /private/stage43_redacted.json
```

Файл `thor43.private-watchpoints.json` содержит **точные адреса и роли** и создаётся с правами доступа `0600` (только владелец). Его нельзя прикладывать к публичному PR. В стандартном выводе и итоговом обезличенном JSON никакие игровые PC и указатели не появляются.

Если доступны **реальные снимки регистров и памяти** с остановок, их можно сохранить локально в формате:

```text
slot-return:       cycle, pc, r0
copy-entry:        cycle, pc, r4, r5
index-store-pre:   cycle, pc, r14, r3
dispatch-entry:    cycle, pc, anchor, r4, index_word
dispatch-jmp-pre:  cycle, pc, r14, index_word, r3 или r2
```

Для отдельного пути `selected_cell` необходим дополнительный снимок `index-word-change` с `pc`, `address=slot+126`, `width_bytes=2`, `old_value=38`, `new_value=0`. Поля PC и физические адреса в журнале — **числа**; значения можно вводить в JSON десятичными целыми. Снимки должны соответствовать одной и той же сессии и монотонно возрастающим значениям `cycle`.

После получения приватного журнала:

```bash
python tools/stage43_private_watchpoints.py "/private/The Story of Thor 2.iso" \
  --manifest-private /private/thor43.private-watchpoints.json \
  --snapshots-private /private/observations.json \
  --summary /private/stage43_redacted.json
```

Инструмент сопоставляет физические адреса и фактические регистры с вычисленными приватно точками входа, а не с опубликованными игровыми позициями. Его положительный результат означает **только согласованность предоставленных наблюдений**; он не может подтвердить, что наблюдения получены действительно в эмуляторе. Поэтому `real_emulator_execution_attested=false` и `real_vdp1_output_attested=false` всегда остаются ложными.

### Практические отладчики

- **Mednafen, Sega Saturn debugger:** `Alt+D` включает отладчик, `Alt+1` открывает CPU-вид, `Space` переключает PC-breakpoint, `Shift+W` задаёт точки остановки на запись; адреса берутся из приватного манифеста. Официальные инструкции: https://mednafen.github.io/documentation/debugger.html
- **Yabause QT:** Master/Slave SH-2 debugger показывает регистры, PC, кодовые/памятные точки остановки и поддерживает Trace Logging. Справка: https://wiki.yabause.org/index.php5?title=Readme_QT

В текущей вычислительной среде Saturn-эмулятор не установлен, поэтому **настоящая трасса не запускалась и кадры игры не воспроизводились**. Эти инструкции предназначены для окружения с доступным эмулятором и законно полученным BIOS.

## Выполненные проверки

- Исходный ISO проверен по SHA-256; приватный манифест для семи ролей успешно создан локально с правами `0600`.
- `tools/stage43_private_watchpoints.py`: приватное обнаружение точек останова, редактированная сводка и проверка полученных извне снимков.
- `tests/test_stage43_private_watchpoints.py`: **42 синтетических теста**, локально 42/42, включая неверные адреса, несоответствие указателей, неправильную цель косвенного JMP, ошибочные индексы, пересечение времён, неявное изменение индекса и приватность итогового JSON.
