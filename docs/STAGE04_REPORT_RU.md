# The Story of Thor 2 — Stage 04: формат индексированных записей

**Дата:** 21.10.2026. **Исходный объект:** приватный ISO Sega Saturn (`MK-81302`, SHA-256 `25b0b2774d4621bd9f95a01fc5420ded37b481b61b3cdf515360d82b2cb7bb0d`). Исходные игровые файлы на GitHub не загружались.

## Подтверждённая структура

Stage 03 определил индексные таблицы с big-endian 16-битными смещениями. В Stage 04 границы каждой записи вычислены из **следующего действительного смещения** либо из конца секции. Значения `0` и `0xFFFF` считаются отсутствующими позициями, а повторяющиеся/обратные смещения не принимаются.

Для **всех 3 730 записей в десяти контейнерах** одновременно выполняются два правила:

1. Длина каждой записи строго `6 + 8 × N`, где `N >= 1`.
2. Первое слово `uint16_be` в записи равно `N - 1`.

Первые 2 байта — счётчик, следующие **4 байта** имеют неизвестное назначение; далее идёт последовательность из **N восьмибайтовых элементов**, содержание которых ещё не интерпретировано.

Это подтверждает **грамматику хранения** в исследованных секциях; **не доказывает**, что элементы являются полигонами, спрайтами, кадрами или координатами.

## Автоматизация

Добавлены `tools/stage04_record_layout.py` и 12 синтетических тестов в `tests/test_stage04_record_layout.py`. Совокупно локально запущен **31 тест** (8 + 11 + 12), все прошли. GitHub Actions запускает тесты без оригинального ISO.

Запуск на *собственной приватной копии*:

```bash
python -m unittest discover -s tests -v
python tools/stage04_record_layout.py "/private/The Story of Thor 2.iso" -o stage04.json
```

В JSON включены только агрегированные значения, без исходных элементов, индексов, графики и видеоданных. Файл `stage04.json` не нужно публиковать, он включён в `.gitignore`.

## Следующая задача (Stage 05)

1. Исследовать 8-байтовые элементы и независимые 6-байтовые записи второй секции; проверить, существуют ли проверяемые связи.
2. Выделить альтернативный структурный разбор для `MONS.BIN` и `P4.BIN`, не насаждая на них неподходящую схему.
3. Проанализировать третий блок каждого контейнера и возможные дескрипторы графики.
4. Проверять результаты визуально локально, прежде чем заявлять об извлечении игровых спрайтов.
5. После определения форматов — приступить к нативной сцене на C++/SDL2 и дальнейшей Switch-сборке.

**Ограничения:** графические декодеры, игровой движок, Nintendo Switch NRO и полное прохождение ещё не разработаны. Вся подтверждённая работа пока касается структурных данных.
