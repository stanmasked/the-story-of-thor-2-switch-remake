# The Story of Thor 2 — Stage 67: вызывающие пути producer-а VDP1

## Результат

Оригинальный ISO найден в папке проекта на Google Drive и сверён с ранее зафиксированной контрольной суммой. Извлечённый исполняемый файл анализировался только в рабочем окружении; ISO, BIN, байты кода и игровые ресурсы в репозиторий не добавлялись.

Статический анализ связывает найденный в Stage 16 генератор дескрипторов с функцией-обёрткой и её вызывающими путями:

- найден один кандидат на функцию, содержащую producer-блок;
- обнаружены четыре прямых BSR-вызова этой функции;
- во всех четырёх задержанных слотах находится MOV R14,R4: обёртка передаёт сохранённый входной указатель дальше в R4;
- сама обёртка имеет три найденных прямых вызывающих места;
- два вызывающих места загружают R4 через индексированный поиск в глобальной таблице указателей по адресу 0x06088B14; третье загружает значение указателя из SP+8 вызывающей функции;
- найден отдельный guard: поле по смещению +0x98 глобального объекта по адресу 0x06088D14 сравнивается со словом по адресу 0x0609BA88. При равенстве ветвление обходит один из вызовов producer-а.

Эти результаты воспроизводятся скриптом tools/stage67_vdp1_producer_callers.py. Он выводит только агрегированные количества и категории происхождения аргументов; позиции инструкций и исходные байты не сериализуются.

## Как читать результат

Установлена статическая цепочка сохранения указателя:

входной R4 обёртки → сохранение в R14 → передача R14 в R4 в задержанном слоте BSR → входной R4 producer-функции.

Для трёх вызывающих мест обёртки видны два пути через глобальную таблицу указателей и один путь через стековый слот SP+8. Это не устанавливает смысл самих указателей, тип объектов в таблице или то, какие значения присутствуют при обычном игровом кадре.

Проверка поля +0x98 — отдельная ветка управления в обёртке. Пока не доказано, что это то же самое поле, из которого producer формирует адрес источника дескриптора; совпадение смещения само по себе не является доказательством алиаса.

## Проверки

- tools/stage67_vdp1_producer_callers.py — поиск сигнатуры producer-а, прямых BSR-вызовов, обёртки, трёх классов происхождения R4 и guard-а +0x98.
- tests/test_stage67_vdp1_producer_callers.py — 12 синтетических тестов: знаковый BSR target, сигнатуры функций, классификация аргументов, проверка field guard, отказ при изменённом целевом вызове, запрет ветвления в delay slot и отсутствие лишних данных в отчёте.
- Тесты не содержат исходных байтов Saturn. Реальный CI для текущего коммита ещё должен завершиться; до этого результаты новых тестов считаются ожидающими подтверждения.

## Что не доказано

- Не установлено, что найденные вызовы выполняются во время обычного игрового кадра.
- Не получен runtime-захват значений R4, R14, глобальной таблицы и локальных стековых слотов.
- Значения и смысл указателя из SP+8 не установлены.
- Поля SP+16 и SP+60, упомянутые в предыдущем отчёте, пока не получили доказанную семантическую интерпретацию.
- Не подтверждено, что глобальный guard +0x98 совпадает с полем источника дескриптора.
- Связь producer-а с submit gate в одном кадре остаётся статической гипотезой; сборка Switch NRO и запуск оригинальной игры не подтверждены.

## Следующий этап

Stage 68: сузить происхождение стековых значений и вложенного указателя, сопоставить стековые слоты с локальными записями и вызовами helper-функций. Затем — подготовить минимальный приватный runtime-захват Saturn, если доступная среда позволит получить синхронные регистры SH-2 и VRAM VDP1.
