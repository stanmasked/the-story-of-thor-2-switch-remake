# The Story of Thor 2 — Stage 44: адреса VDP1 и офлайн-анализ команд видеопамяти

Дата: 22.10.2026. Приватно проверен исходный Sega Saturn ISO MK-81302, SHA-256 `25b0b2774d4621bd9f95a01fc5420ded37b481b61b3cdf515360d82b2cb7bb0d`. Игровые исполняемые байты, ISO, точные позиции кода, видеопамять и графические ресурсы не размещены в публичном GitHub.

## 1. Первый подтверждённый адресный ориентир VDP1

В `0TH2.BIN` обнаружены PC-относительные `MOV.L @(disp,PC),Rn`, которые загружают известные базовые адреса аппаратных областей Saturn:

| Назначение адреса | Значение | Загрузок из литералов |
|---|---|---:|
| VRAM VDP1 (512 КиБ) | `0x25C00000` | **6** |
| Регистры VDP1 | `0x25D00000` | **3** |

Эти адреса соответствуют официальной карте памяти Sega Saturn и справочнику Yabause: https://wiki.yabause.org/index.php5?title=VDP1 ; https://www.infochunk.com/saturn/segahtml_en/hard/vdp1/hon/p06_10.htm .

Это **синтаксически подтверждённые загрузки аппаратных адресов**, а не девять записей VRAM или регистров. Статический код ещё не связывает их с обработчиком №39; факт запуска команд VDP1 пока не наблюдался.

## 2. Реализован парсер приватного дампа VRAM

Инструмент `tools/stage44_vdp1_vram_audit.py` принимает необязательную **пару приватных** дампов VRAM по 524288 байт. Обрабатывает 32-байтные записи VDP1: `CMDCTRL` (`END`, `JP`, тип), `CMDLINK` (адрес записи в единицах по 8 байт), `CMDSIZE` (размеры спрайта). Для JP поддержаны переходы `NEXT`, `ASSIGN`, `CALL`, `RETURN` и соответствующие четыре формы `SKIP`. Ограничение на один уровень вложенных `CALL` выбрано согласно аппаратному формату VDP1.

Парсер начинает с первой команды VRAM, различает достижение `END`, неверный адрес, нарушение выравнивания 32 байта, неразрешённый `RETURN`, попытку вложенного `CALL`, цикл и превышение лимита команд. Он считает группы типов команд (спрайт, полигон, линии, clipping, local coordinates), число пропущенных команд и записи-кандидаты с нулевыми размерами спрайта.

При сравнении двух дампов выдаются только агрегированные числа: изменившиеся байты всего VRAM, число уникальных посещённых командных ячеек, число изменившихся посещённых 32-байтных команд. Данные текстур могут меняться вне области команд и учитываются только в общем счётчике байтов.

**Существенное ограничение:** интерпретировать любой дамп как реальную командную цепочку VDP1 можно только при известном контексте захвата. Даже корректное достижение `END` не подтверждает, что процессор VDP1 действительно исполнил цепочку. Парсер не рисует пиксели и не декодирует палитры/текстуры.

## 3. Локальный запуск

Статический аудит оригинального ISO без дампов:

```bash
python tools/stage44_vdp1_vram_audit.py "/private/The Story of Thor 2.iso" \
  -o /private/stage44_static_summary.json
```

После захвата настоящих сырых байтов VRAM с помощью отладчика Saturn-эмулятора **до и после конкретного события** (расположение VRAM VDP1: `0x25C00000`, размер `0x80000` байт):

```bash
python tools/stage44_vdp1_vram_audit.py "/private/The Story of Thor 2.iso" \
  --before-vram-private /private/vdp1_before.bin \
  --after-vram-private /private/vdp1_after.bin \
  -o /private/stage44_redacted.json
```

В Mednafen memory editor поддерживает дамп памяти через `D`; формат описан на https://mednafen.github.io/documentation/debugger.html. При выборе адресного пространства в отладчике необходимо убедиться, что получены именно **сырые 512 КиБ VDP1 VRAM**, без заголовка и перестановки байтов. В этой вычислительной среде полноценный Saturn-эмулятор и необходимый BIOS отсутствуют, реальные дампы не получены.

Не публиковать дампы, файлы c debugger PC и сырые журналы кадров; они могут содержать исходную графику игры. Репозиторий хранит только код, синтетические тесты и обезличенные метрики.

## 4. Проверки

- На приватном `0TH2.BIN`: 6 PC-relative загрузок VRAM и 3 загрузки регистров.
- `tests/test_stage44_vdp1_vram_audit.py`: **33 полностью синтетических теста** переходов, END, циклов, вложенных CALL, ограничений, типов, сравнения двух дампов и запрета ложных утверждений об исполнении; локально 33/33.
- Не подтверждены запись команд VDP1 обработчиком №39, динамическая связь экземпляра клонированного 276-байтного объекта с командным буфером, исходный цветовой формат, декодер пикселей или запускаемая Switch NRO.
