# The Story of Thor 2 — Stage 111: изоляция записи байта и конвейера SH-2

## Основание

Stage110 зафиксировал в двух независимых приватных сессиях по 192 пары состояния SH-2 с PC-триггером поздней записи, а в третьей — 4096 пар. Во всех наблюдавшихся состояниях значение R13 равно единице, однако **полный возврат не наблюдался**. Дополнительный разбор в приватной среде обнаружил, что после начальной последовательности 4096-шаговый захват повторяет четырёхадресный участок кода более тысячи раз. Поле RPC описывает конвейер, а не обязательно текущую исполняемую инструкцию. Поэтому статус «R13=1 у исходного PC» не равен непосредственному свидетельству байтового изменения памяти.

## Метод Stage111

Добавлен публичный патчер `tools/stage111_patch_mednafen_memory_witness.py`, который устанавливается **после** Stage109 на исходники открытого Mednafen 1.29.0. Он вводит отдельный, по умолчанию отключённый свидетель RAM-байта из физического high work RAM. Вместо MMIO-методов эмулятора используется прямое, не имеющее побочных эффектов чтение из backing array `WorkRAMH`, которое выбирается строго после проверки диапазона R3. Пара `pre/post` фиксирует значения указателя, байта и PC-контекста до и после шага Master SH-2. Вся сырая запись направляется исключительно в локальный файл при отдельном opt-in и указанном **локально** приватном PC.

Экспортируемых в GitHub адресов, байтов из игры, ISO, BIOS и логов регистров нет. Public CI собирает только открытый исходный код, выполняет синтетические тесты и выдаёт короткоживущий бинарный артефакт.

## Граница доказательства

Даже выявленное изменение RAM-байта при одном шаге — самостоятельное доказательство состояния backing storage, **не автоматическая аттестация конкретного опкода** из-за конвейера SH-2 и возможных других записывающих источников. Для окончательной привязки потребуются согласование opcode/реальной фазы выполнения, защита от сторонних писателей и повторный независимый захват. Отсутствие изменения в ограниченном интервале также не доказывает отсутствие записи или недостижимость поздней программы.

Пока точный вызов-возврат, фактическое содержимое RAM после `MOV.B` и безусловная гипотеза Stage104 **не подтверждены**.
