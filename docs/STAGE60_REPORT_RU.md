# The Story of Thor 2 — Stage 60: приоритеты и тени спрайтов VDP2

Дата: 22 октября 2026 года.

## Результат анализа

Stage59 научился читать приватную VDP2 CRAM и предварительно связывать цветовые коды спрайтов с палитрой. Однако значение из CRAM ещё не является видимым пикселем. Экран Saturn компонует слои по приоритетам, выполняет цветовые расчёты и может трактовать специальные пиксели как команды создания тени.

Stage60 впервые проверяет **восемь регистров приоритета спрайтов, восемь цветовых коэффициентов и аппаратные правила теней**. Основание — документация самой Sega:

- [VDP2 User's Manual — Sprite type Figure 9.1](https://www.infochunk.com/saturn/segahtml_en/hard/vdp2/hon/p09_10.htm)
- [VDP2 register bit configuration — PRIS, CCRS, SPCTL, SDCTL](https://www.infochunk.com/saturn/segahtml_en/hard/vdp2/hon/p15_30.htm)
- [Sega Saturn Technical Bulletin #25 — reserved normal-shadow codes](https://docs.exodusemulator.com/Archives/SSDDV25/segahtml/info/hon/stn25.htm)
- [Sega Saturn Technical Bulletins — MSB shadow requirements](https://antime.kapsi.fi/sega/files/Sattechs.pdf)

**Базовое различие:** номер выбора приоритета PR в пикселе — это *индекс одного из восьми регистров S0PRIN…S7PRIN*, а не непосредственная высота слоя. Значение регистра от 0 до 7 лишь участвует в аппаратном разрешении приоритетов, вместе с фоном, окнами, тенями и цветовыми режимами.

## Реализовано

Новый `tools/stage60_vdp2_sprite_priority_shadow.py`:

1. Читает из полного 512-байтного приватного дампа регистры `SPCTL` (+0xE0), `SDCTL` (+0xE2), `CCCTL` (+0xEC), пары `PRISA–PRISD` (+0xF0–F6) и `CCRSA–CCRSD` (+0x100–106).
2. Декодирует младшее трёхбитное поле приоритета и трёх-/пятибитные поля второй записи в каждой паре (по 3 бита на SxPRIN, 5 бит на SxCCRT). Получает восемь регистров аппаратного приоритета и восемь значений коэффициентов, **не смешивая** коэффициенты с готовой прозрачностью.
3. Для 16-битных форматов спрайта `SPTYPE 0–7` реализует таблицу декодирования длины полей DC/CC/PR/SD из Figure 9.1. Для типов `8–F` оставляет отметку `unresolved`, поскольку это другие 8-битные схемы буфера кадра.
4. Распознаёт *зарезервированный обычный код тени*, когда все биты DC кроме младшего равны 1: например `0x7FE`, `0x3FE` или `0x1FE` в зависимости от формата спрайта. Он не должен ошибочно превращаться в цвет палитры. По маске SDCTL отдельно отмечается, включена ли функция тени на соответствующих фоновых экранах.
5. Проверяет **только возможность MSB-тени**: типы 2–7, SPWINEN=0 и SPCLMD=0. Если выбрана `TPSDSL` (SDCTL bit8), помечает потенциальную прозрачную MSB-тень `0x8000`, для которой используется регистр приоритета спрайта №0. Без подтверждённого VDP1 MSBON и итогового кадрового буфера это остаётся *кандидатом*, а не настоящей нарисованной тенью.
6. Для прямого RGB сохраняет правило Sega: поля PR/CC считаются нулевыми, используется регистр №0. При включённом CCCTL.SPCCEN отмечает лишь возможность цветовых расчётов, а не вычисляет итоговое смешивание.
7. Обрабатывает вместе три приватных файла: VDP1 VRAM (524288 байт), VDP2 CRAM (4096 байт), VDP2 регистры (512 байт). Каждый пиксель проходит уже существующие правила Stage58 и Stage59; анализ ограничен по количеству команд и пикселей.

Публично-безопасный JSON содержит **только агрегаты**: число пикселей по категориям, частоту выбора приоритетов 0–7, декларированные значения регистров и лимиты. Данные оригинальных пикселей, точные адреса, отдельные слова VDP1/CRAM и игровые кадры не экспортируются.

## Ограничения, принципиальные для точности

- Содержимое текстуры VDP1 из Stage58 *не тождественно* уже сформированным пикселям буфера кадра VDP1: там могла применяться команда MSBON, clipping, Gouraud, mesh, полупрозрачность или запись в другой framebuffer. В Stage60 аппаратные варианты помечены как условные.
- Значение `SDCTL` не означает, что тень возникла: требуется подходящий пиксель, активный фон под ним и аппаратная обработка.
- Приоритет 0 в VDP2 — кандидат на прозрачность; полный порядок экранов и правила совпадения приоритетов ещё не восстановлены.
- Без настоящих синхронных игровых дампов RAM/VRAM/CRAM нельзя утверждать, что эти сочетания встречаются в The Story of Thor 2.
- Этот модуль не рисует итоговые кадры и не создаёт Nintendo Switch NRO.

## Приватный запуск

Сверка исходного ISO без выполнения эмулятора:

```sh
python tools/stage60_vdp2_sprite_priority_shadow.py \
  --iso-private "/private/The Story of Thor 2.iso"
```

Разбор будущего синхронного приватного захвата:

```sh
python tools/stage60_vdp2_sprite_priority_shadow.py \
  --iso-private "/private/The Story of Thor 2.iso" \
  --vdp1-vram-private "/private/capture/vdp1.private-vram" \
  --vdp2-cram-private "/private/capture/vdp2.private-cram" \
  --vdp2-regs-private "/private/capture/vdp2.private-registers" \
  --output-private "/private/capture/stage60.private-priority-shadow.json"
```

Приватный отчёт создаётся новым файлом с правами `0600`, без перезаписи. Никакие исходные графические байты не отправляются в публичный GitHub.
