# The Story of Thor 2 — Stage 84: CFG-порядок непарного callback и выравнивание сервисного слота

## Результат локального анализа оригинального ISO

### 1. Прямой CFG уточняет порядок callback/writer в TH2.LOW

Для единственного кандидатного интервала, содержащего непарный callback ID 64 и более поздний writer-callsite, выполнен обход прямого SH-2 control flow с учётом условных переходов, BSR/JSR, delay slots, возвратов и границ функции.

- Посещено **722** состояния CFG.
- Исправленный анализатор повторно запущен на приватном ISO: посещено **722** состояния CFG, а callback имеет только состояние «writer ещё не вызывался» (`callback_reachability_states = 1`; все достижимые callback-состояния имеют `writer_seen = false`).
- Writer-callsite достижим в двух состояниях: по пути после callback и по отдельному пути без предварительного callback.
- В пределах этого ограниченного прямого CFG путь «writer → затем этот callback» не найден; наблюдаемый порядок — «callback → затем writer» либо отдельный путь к writer.

Этот результат подтверждает только порядок в исследуемом интервале при текущей модели прямого CFG. Он не исключает инициализацию поля другой функцией, альтернативный вход в код, таблицы/вычисляемые переходы или ранее сохранённое состояние.

### 2. Сырые вхождения сервисного слота не являются выровненными указателями

В `TH2.LOW` повторно исследованы 38 сырых big-endian вхождений значения адреса сервисного слота A:

- все 38 начинаются с нечётного байтового смещения;
- ни одно не выровнено даже по 16-битной границе, поэтому ни одно не выровнено как 32-битный указатель;
- ни одно не распознано как слово literal pool, на которое указывает `MOV.L @(disp,PC),Rn`;
- для слота B сырых вхождений не найдено.

Эти 38 совпадений — только поиск байтовой последовательности. Их нельзя интерпретировать как 38 записей таблицы или как доказательство регистрации сервисного указателя. Предыдущий Stage82 уже отмечал отсутствие прямых PC-relative загрузок адреса слота; Stage84 дополнительно показывает, что сырые совпадения не являются выровненными longword-элементами.

## Изменения

Добавлен `tools/stage84_low_cfg_order_and_slot_alignment.py` с агрегированным CFG-анализом пары callback/writer и проверкой выравнивания сырых адресных вхождений. Добавлены десять синтетических тестов для порядка вызовов, альтернативных ветвей, raw-совпадений и literal-pool классификации.

## Следующий этап — Stage 85

1. Проследить вызывающие цепочки трёх writer-вызовов из `TH2.LOW` и двух copy-путей из `0TH2.BIN`.
2. Исследовать сервисные RAM-слоты через вычисляемые адреса, указатели на таблицы и код runtime, не считая сырые совпадения доказательством.
3. Проверить, есть ли путь инициализации общего поля до двух copy-чтений вне рассматриваемых функций.
4. Не заявлять глобальный предел длины, завершение DMA или кадровую синхронизацию без полной цепочки доказательств.

**Статус:** один подозрительный callback/writer-контекст проверен CFG: writer не предшествует этому callback на обнаруженных прямых путях. Сырые совпадения сервисного слота оказались невыровненными байтовыми вхождениями. Глобальная инициализация источника и runtime-поведение остаются открытыми.
