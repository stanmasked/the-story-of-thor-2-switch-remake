# The Story of Thor 2 — Stage 48: приватная проверка копирования команд VDP1

Дата: 22.10.2026. Stage 47 и 46 проверены синтетическим GitHub CI, но **новой трассы оригинальной игры на Saturn в данной сессии нет**. Этот этап создаёт проверяемый *офлайн-контракт* между копировщиком Stage 45, управляющим кодом Stage 46 и будущими частными захватами памяти.

## Главная техническая неопределённость

Stage 16 обнаружил кандидатную функцию, добавляющую по одному 8-байтному дескриптору и увеличивающую общий счётчик на 1. Повторная проверка инструкций Stage 45 установила: **R2 уменьшается на 1 за каждую 32-байтную команду во внутреннем цикле, R5 уменьшается на 1 за каждый завершённый 8-байтный дескриптор во внешнем цикле**. Stage 46 загружает R5 из глобального счётчика.

Для корректного R5 требуется совпадение со **счётчиком дескрипторов**; количество команд вычисляется отдельно из суммы полей +6. Stage 48 теперь проверяет:

    pending_count_before == len(descriptors)
    copied_commands == sum(descriptor.copy_count)

Он является **необходимым условием для рассматриваемой идеализированной модели**, а не доказательством достижения или безопасного завершения настоящего SH-2 цикла.

## Новый инструмент

- `tools/stage48_vdp1_copy_witness.py` принимает локальные метаданные (флаг, счётчики и записи назначения), два полных снимка VRAM по 524288 байт и, по желанию, конкатенацию 32-байтных исходных команд в порядке дескрипторов.
- Необходимо передать `copy_count` **положительным**, а `destination_index` — беззнаковым 16-битным числом. Проверяется адрес `index * 8 + copy_count * 32 <= 524288`, размер каждого частного файла, количество записей до 512 (консервативный лимит аудитора), суммарное число команд до 16384. Все пределы инструмента ограничивают анализ, **не доказывают** ограничения реальной программы.
- Без исходного потока команд доступны только геометрия областей и число изменившихся байт. При наличии потока формируется ожидаемая VRAM путём последовательных копий и проверяется точное совпадение с состоянием после захвата.
- Отдельно считаются изменения *внутри* предполагаемых диапазонов и *вне* их, перекрытия записи, 32-байтное выравнивание назначения и соответствие исходного флага и сбросов.
- Отчёт выводит только агрегаты, без адресов, дампов, исходных машинных байтов, изображений и игровых ресурсов. Результат **никогда не утверждает, что происхождение снимков из эмулятора установлено**.

## Формат исключительно приватного manifest.json

Пример ниже полностью синтетический. **Не добавляйте в GitHub реальные дампы, источники или заполненные манифесты игры.**

```json
{
  "schema_version": 1,
  "status_before": -1,
  "status_after": 0,
  "pending_count_before": 2,
  "pending_count_after": 0,
  "descriptors": [
    {"destination_index": 0, "copy_count": 1},
    {"destination_index": 8, "copy_count": 1}
  ]
}
```

Два полных VRAM-снимка должны относиться к состояниям **непосредственно до JSR и непосредственно после возврата**, насколько это позволяет отладчик. Для необязательного бинарного файла источников конкатенируйте реально захваченные из памяти 32-байтные команды подряд, сначала все команды первого дескриптора, затем второго и т.д. Не используйте данные из ISO вместо живых источников без отдельного доказательства их совпадения.

Запуск вне GitHub, из локального каталога репозитория:

```sh
python tools/stage48_vdp1_copy_witness.py \
  --manifest-private /private/thor48/capture.json \
  --before-vram-private /private/thor48/before.vram \
  --after-vram-private /private/thor48/after.vram \
  --source-commands-private /private/thor48/sources.bin \
  --output-private /private/thor48/audit.private-copy-witness.json
```

Без исходного потока можно опустить `--source-commands-private`. Результат `--output-private` создаётся как **новый** файл с правами 0600; перезапись/следование по существующему симлинку запрещены. Секретные файлы нельзя сохранять в репозитории. Файл с подлинными командами содержит защищённые игровые байты и не передаётся в CI.

Оригинальный ISO найден в закрытой папке Google Drive `Story of Thor 2` и обработан **только локально**. Его SHA-256 совпал с ранее задокументированной контрольной суммой `25b0b2774d4621bd9f95a01fc5420ded37b481b61b3cdf515360d82b2cb7bb0d`. Из ISO приватно извлечён `0TH2.BIN`; никакие игровые байты/адреса в GitHub не загружены.

Это **независимая приватная повторная проверка сигнатур**, а не запуск полнофункционального дизассемблера или наблюдение реальных переходов. Отдельный кандидат установки отрицательной константы может оказаться полезным следующим ориентиром; его исполнение, тип события и связь с источниками команд пока неизвестны. Распознаватель производителя в этой дополнительной проверке использует ограниченный характерный набор инструкций, поэтому его результат считается *кандидатом*, а не строгим доказательством идентичности всех путей.

Проверка Stage48 на двух **настоящих** дампах VRAM не выполнена: этих захватов в текущем окружении пока нет. Никакие числовые результаты реконструкции команд для настоящей игры не заявляются.

## Синтетические тесты

`tests/test_stage48_vdp1_copy_witness.py` содержит 39 тестов: арифметика бюджета, правильный и неправильный прогноз, пересечения/границы VRAM, смешанные изменения, проверки входной схемы, ограничение размеров, приватные файловые права, отсутствие данных оригинала в отчёте. Локально 39/39. GitHub CI проверяет только код на синтетических данных.

## Выводы и следующий шаг

Данный этап предоставляет способ **отбраковать неподходящие трассы** и найти противоречия между моделями производителя и загрузчика. Даже результат `copy_path_consistent_with_observation=true` означает лишь *согласованность предоставленных снимков с моделью*, но не подлинность, реальный вызов, причинную связь с обработчиком №39, выполнение VDP1 или графическое декодирование.

Следующий этап: частный запуск игры в отладчике Saturn, снятие R4/R5, знакового флага и исходных 8-байтных дескрипторов перед вызовом Stage45, полный VRAM до/после, захват источников, сравнение и отдельная проверка принадлежности события объекту с индексом 38. Никаких оригинальных данных в публичный GitHub.

## Исправление после повторного SH-2-аудита

Первоначальная формулировка Stage 48 ошибочно относила декремент R5 к внутреннему циклу. На самом деле внутренний счётчик — R2, внешний — R5. Исправлены расчёт согласованности и синтетические проверки случая одного дескриптора с двумя командами. Дата исправления 22.10.2026. Старые результаты такого контракта не следует использовать как доказательство корректности захвата.
