# The Story of Thor 2 — Stage 81: перепись литерал-зависимых вызовов callback ID 64

## Результат локального анализа оригинального ISO

В приватном образе `The Story of Thor 2.iso` просканированы PC-relative загрузки адреса callback ID 64 с непосредственно следующим `JSR @Rn`. Исходный ISO и извлечённый код остаются вне GitHub.

Обнаружены четыре литерал-зависимые точки вызова, которые делятся на два устойчивых шаблона:

1. **Два вызова writer → callback.** Перед callback-вызовом находится вызов исследованной функции-писателя; между ними выполняются delay slot первого `JSR` и загрузка адреса callback, без условного перехода.
2. **Два вызова с присваиванием поля длины в delay slot.** Перед callback-вызовом читается слово из общего поля-источника, а delay slot самого callback-вызова записывает его в поле длины/счётчика.

Таким образом, все четыре обнаруженные литерал-зависимые точки соответствуют одному из этих двух шаблонов; нераспознанных точек среди них нет. Это не означает, что найден каждый возможный вызов: указатели из RAM-таблиц, вычисляемые цели и runtime-регистрация могут обходить PC-relative literal-load шаблон.

## Важное уточнение

Два вызова с присваиванием поля длины **не имеют непосредственно предшествующего вызова writer**. Они используют текущее значение общего поля-источника и переносят его в поле длины в delay slot. Поэтому Stage80 доказывает writer-before-callback только для двух других конкретных последовательностей, но не доказывает, что источник был инициализирован до первого чтения в этих двух copy-путях.

Это не доказательство ошибочного поведения игры: значение могло быть установлено ранее через другой достижимый путь. Требуется найти вызывающий контекст обеих copy-функций и проверить их цепочку вызовов, альтернативные ветви и возможные инициализаторы.

## Следующий этап — Stage 82

1. Найти содержащие функции двух copy-вызовов и проследить их вызывающие цепочки.
2. Проверить, достигает ли вызов writer этих функций до чтения поля-источника либо источник инициализируется другим путём.
3. Проверить табличные и вычисляемые вызовы callback ID 64, не полагаясь только на PC-relative литералы.
4. Не заявлять инициализацию источника до первого использования, глобальный предел длины, завершение DMA или кадровую синхронизацию без полной цепочки доказательств.

**Статус:** четыре прямых литерал-зависимых callsite классифицированы; две пары writer → callback статически подтверждены, две copy-последовательности остаются зависимыми от ранее установленного значения источника. Глобальная инициализация и runtime-порядок остаются открытыми.
