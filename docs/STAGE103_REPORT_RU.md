# The Story of Thor 2 — Stage 103: аргументы системного вызова и гипотеза SYS_CHGSCUIM

## Сопоставление с документацией

В официальном System Program User's Manual Sega функция `SYS_CHGSCUIM` описана как `SYS_CHGSCUIM(AndMask, OrMask)`: текущее значение маски SCU объединяется с первым аргументом через AND, затем со вторым через OR; результат записывается в состояние маски. Документация: https://www.infochunk.com/saturn/segahtml_en/prgg/sysg/prog/hon/p02_11.htm .

Независимый разбор SGL `_slInitSystem` также называет вызов через низкоадресный function-pointer slot как `SYS_CHGSCUIM` и показывает аргументную форму с маской в `R4` и нулём в `R5`: https://github.com/vs-sr-dev/pc-deepfear/blob/main/docs/03-executables.md . Это внешнее сопоставление с другим SGL build, не доказательство содержимого указателя в нашем запуске.

## Результат по оригинальному ISO

Локальная bounded-проверка аргументов нашла 10 slot-call patterns в игровых root payloads и ещё один в ограниченном boot-code window. Все 11 пар удалось разрешить в bounded linear windows:

- 8 вызовов имеют отрицательный R4 mask-кандидат и нулевой R5.
- 3 вызова имеют отрицательный R4 mask-кандидат и небольшой ненулевой R5.
- В root payloads шесть вызовов используют PC-relative word для R4 и нулевой R5; два — immediate для R4 и нулевой R5; ещё два — immediate для R4 и небольшой ненулевой R5.

Такая форма аргументов совместима с документированным интерфейсом `SYS_CHGSCUIM`. В сочетании с ранее найденным одинаковым slot-dereference/indirect-JSR шаблоном в `0TH2.BIN`, `SET07.BIN` и boot-code window это делает `SYS_CHGSCUIM` **высоковероятной статической гипотезой** для функции, на которую указывает slot.

Известные ограничения: аргументы восстановлены по ближайшим записям регистров в ограниченном линейном окне, а не доказаны для всех CFG-путей. В ISO не найдено проверенных текстовых баннеров из узкого списка `GFS_SGL`, `STM_SGL`, `SGL Version`, `GFS Version`, `SYS Version` и `_slInitSystem`; отсутствие этих строк не доказывает отсутствие SGL, так как библиотеки могут быть stripped или собраны без баннеров.

## Что установлено и что нет

**Установлено статически:** форма всех 11 call patterns совместима с двумя аргументами маски; документированная семантика `SYS_CHGSCUIM` объясняет наблюдаемую форму аргументов лучше, чем гипотеза о произвольном игровом callback.

**Не установлено:** фактическое runtime-содержимое slot, адрес/идентичность цели во время игры, поведение конкретной ROM-реализации функции, сохранение R13 этой реализацией, фактическое значение control byte, выбор error-ветвей, callback registration, overlay execution, DMA completion и same-frame graphics timing.

Поэтому вывод Stage 99 остаётся условным. Идентификация `SYS_CHGSCUIM` имеет высокую статическую правдоподобность, но пока не является runtime-доказательством. ABI-ожидание сохранения callee-saved регистров само по себе не доказывает поведение конкретной реализации в BIOS.

## Реализация и тесты

Добавлен `tools/stage103_sys_chgscuim_argument_audit.py`. Он разрешает ограниченное происхождение констант для `R4`/`R5`, учитывает запись аргумента в delay slot и выдаёт только агрегированные категории. Конкретные аргументные значения, RAM-адреса, смещения инструкций, байты кода и игровые payloads в отчёт не попадают.

Добавлено восемь синтетических тестов: знаковый immediate, PC-relative word, копирование регистра, приоритет delay slot, нулевой R5, неразрешённая загрузка из памяти, категории пар и агрегированный отчёт без местоположений или сырых значений. Результат GitHub Actions будет добавлен в приватный манифест после завершения запуска.
