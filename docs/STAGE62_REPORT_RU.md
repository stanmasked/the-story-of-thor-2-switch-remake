# The Story of Thor 2 — Stage 62: первая запускаемая нативная игровая песочница

Дата: 22 октября 2026 года.

## Что нового

После Stage61 мы впервые имеем компилируемый нативный графический C++17 модуль, но игрового движения, ввода и вывода изображения не было. Stage62 добавляет **самостоятельную запускаемую host-демонстрацию**, не содержащую оригинальных спрайтов, уровней, сценариев и ROM.

Новые файлы:

| Файл | Назначение |
|---|---|
| `native/gameplay.hpp` | Детерминированная модель карты и игрока, ввод, столкновения, сбор трёх тестовых кристаллов, выход |
| `native/software_renderer.hpp` | Программный RGBA-буфер 320×240, камера, плитки, стены, герой, предметы, HUD |
| `native/demo/sandbox_cli.cpp` | Исполняемая host-демонстрация с WASD, текстовой картой, скриптовым вводом, экспортом PPM |
| `native/tests/sandbox_test.cpp` | Независимые C++-тесты детерминизма, карты, маршрута к победе, столкновений и рендеринга |
| `.github/workflows/python-tests.yml` | Новая job `native-gameplay-host`, сборка двух C++ программ, тесты, smoke-test PPM, публикация артефакта Linux |

**Важно:** это не исполняемая копия The Story of Thor 2. Карта, внешний вид игрока и механика трёх кристаллов созданы для технического прототипа. Никаких оригинальных персонажей, уровней, текстур, музыки или кода Sega в новых исходниках нет.

## Игровой цикл и физика

- Фиксированный шаг **60 тиков/секунду**, без плавающей точки в логике.
- Движение героя по WASD: 3 пикселя за тик по одной оси и 2 пикселя по каждой оси при диагональном вводе.
- Герой занимает прямоугольник **12×12** пикселей; столкновения с 16-пиксельными плитками проверяются по одному пикселю на каждом подшаге. Это предотвращает проскок стен и позволяет скользить вдоль препятствий.
- Камера 320×240 следует за героем с ограничением координат внутри карты 48×30 плиток.
- Три условных кристалла собираются при физическом пересечении прямоугольников; выход на другом конце уровня требует все три и отдельного нажатия E рядом с ним.
- Ввод E обрабатывается по фронту (одно взаимодействие при нажатии), R сбрасывает игровое состояние, после победы положение игрока больше не изменяется.
- `state_hash()` использует стабильный FNV-1a для сопоставления детерминированных replay-последовательностей.
- Рендерер рисует только прямоугольники и простые собственные цвета. Для проверки изображения рассчитывается отдельная контрольная сумма `Surface::fnv1a()`.

## Сборка и запуск на Linux/macOS

Требуется компилятор с C++17; SDL, libnx, BIOS и оригинальный ISO **не требуются**.

```sh
g++ -std=c++17 -O2 -Wall -Wextra -Werror -pedantic -Inative \
  native/demo/sandbox_cli.cpp -o thor2-sandbox

./thor2-sandbox
```

В терминале отображается условная карта (20×15 плиток). `@` — тестовый герой, `#` — препятствие, `*` — кристалл, `X` — закрытый выход, `O` — открытый выход. Управление: `w`, `a`, `s`, `d` или диагональная комбинация `wd`; `e` — взаимодействие с выходом, `r` — начать заново, `q` — закончить. После комбинации клавиш можно указать количество тиков, например `d 25` или `wd 8`. Допустимо 1–120 тиков за команду.

Запуск полностью воспроизводимого скрипта и сохранение **неигрового тестового кадра** PPM:

```sh
./thor2-sandbox --script="d 20;s 7;e 1" \
  --ppm=/tmp/thor2-demo.ppm --quiet
```

Результат: файл PPM в формате RGB 320×240, в stdout — хэши состояния и кадра. Файл можно открыть обычным просмотрщиком PPM или преобразовать в PNG. В GitHub Actions Linux-бинарник и этот синтетический кадр публикуются в артефакте `stage62-linux-host-sandbox`.

## Проверки в GitHub Actions

Старые 1438 тестов Stage61 остаются в общей CI. Дополнительно CI Stage62 выполняет:

1. Компиляцию тестов и нативного host-демо на `g++ -std=c++17 -O2 -Wall -Wextra -Werror -pedantic`.
2. Движение, столкновения, диагональный ввод, столкновение со стеной и скольжение, граничные условия камеры, детерминированный replay и полный **синтетический маршрут до победы**.
3. Тест программной отрисовки, цветов, HUD, хэша кадра, граничных координат и запрета огромных прямоугольников.
4. Программный запуск демонстрации без участия пользователя и проверку того, что PPM содержит ровно `320 × 240 × 3` цветовых байта.

## Что дальше

Нативный прототип ещё **не является Switch NRO**. На следующем этапе нужно добавить библиотеку платформенного ввода и реальный графический backend для Nintendo Switch (devkitPro/libnx), не изменяя правила игровой логики, а также разрабатывать анимации, скрипты сцен и бой на собственных тестовых ресурсах. Подлинная игра для Saturn пока не исполняется в локальном эмуляторе, а восстановление её ресурсов остаётся приватным отдельным направлением.
