# The Story of Thor 2 — Stage 96: расширенный аудит записей dispatch-slot

## Источник и приватность

Оригинальный ISO прочитан локально из приватной рабочей среды. Просканированы корневые файлы диска; бинарный образ, извлечённые данные, адреса инструкций и смещения не добавлялись в репозиторий. Из 33 корневых файлов 30 файлов размером до 5 MiB проверены полностью; три больших CPK-контейнера исключены из сканирования кода ограничением размера.

## Результаты оригинального ISO

- Сохранены 13 точных PC-relative literal-load ссылок на общий dispatch-slot: 3 в `0TH2.BIN`, 7 в `TH2.LOW` и 3 в `SET07.BIN`.
- Расширенный поиск проверил 14 загрузок указателей, чьи значения находятся в пределах 0x80 байт от целевого slot. Для каждой загрузки анализировалось до 128 последующих инструкций, с распространением простых `MOV`/`ADD`-алиасов и учётом delay slot у обнаруженного control transfer.
- **Разрешённых кандидатов записи по точному адресу slot не найдено**: ни прямых indirect/predecrement stores, ни displacement stores, ни stores, адрес которых удалось получить через простой alias или арифметику.
- Найден один неразрешённый indexed-byte-store кандидат в `MONS.BIN`. Его базовый адрес находится рядом с slot, но индекс `R0` в локальном окне не удалось определить. Поэтому нельзя ни подтвердить, ни исключить попадание этой записи в целевую ячейку.

## Интерпретация

Расширенный bounded scan не нашёл writer-а, который можно было бы доказательно привязать к dispatch-slot. Это уточняет Stage 95, но не доказывает отсутствие инициализатора: анализ ограничен PC-relative literal-load источниками, простыми алиасами, окном в 128 инструкций и тремя крупными файлами, исключёнными из полного code scan.

Найденный indexed-store в `MONS.BIN` оставлен как открытая неопределённость, а не засчитан как writer. Для подтверждения потребуется проследить происхождение `R0` по реальному CFG и проверить, достижима ли эта инструкция в контексте записи.

## Реализация и проверки

Добавлен `tools/stage96_dispatch_slot_writer_alias_census.py`. Он использует расширенный bounded alias scan по каждому доступному корневому payload и отдельно различает точные literal-ссылки, сырые совпадения адресных слов, точные store-кандидаты и неразрешённые indexed-store-кандидаты. Отчёт содержит только агрегированные счётчики по модулям.

Добавлено 8 синтетических тестов для прямой записи, `ADD`-алиаса, displacement/predecrement stores, неверного регистра, delay-slot store и различия между сырым словом и PC-relative ссылкой. В локальной проверке алгоритма все 8 контрольных сценариев прошли. GitHub Actions для новой ревизии ещё ожидает исполнителя; полный CI-результат не заявляется.

## Следующий этап — Stage 97

1. Разобрать происхождение `R0` в единственном indexed-store кандидате `MONS.BIN` и проверить, может ли его эффективный адрес совпасть с dispatch-slot.
2. Проследить две optional косвенные цели error-helper-а в низкой RAM и искать источник их кода или динамического размещения, не подбирая базу только по совпадению смещений.
3. Если indexed-store окажется нерелевантным, расширить поиск writer-ов на CFG-пути и межпроцедурные aliases; если релевантным — восстановить контекст инициализации slot.
4. Оставить callback/service-slot регистрацию и runtime-поведение неподтверждёнными до прямого свидетельства.

**Границы вывода:** 13 literal-backed ссылок подтверждены; в bounded scan нет разрешённых writer-кандидатов и есть один неразрешённый indexed-store. Источник инициализации, runtime-значение dispatch-slot, callback invocation, overlay execution, DMA completion и same-frame graphics timing остаются открытыми.
