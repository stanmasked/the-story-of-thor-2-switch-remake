# The Story of Thor 2 — Stage 29: восстановлена функция Q8.8-преобразования

Дата: 21.10.2026. Исходный Sega Saturn ISO MK-81302 исследован приватно; SHA-256 `25b0b2774d4621bd9f95a01fc5420ded37b481b61b3cdf515360d82b2cb7bb0d`. Публичный репозиторий содержит только инструменты и синтетические тесты, но не исходные программные байты, позиции в бинарном файле или графические ресурсы.

## 1. Разрешение косвенного вызова

На Stage 28 выявлены две группы условных преобразований, каждая вызывающая `JSR @R13`. Теперь проверен `MOV.L @(disp,PC),R13`, загружающий один и тот же абсолютный адрес функции; PC вычисляется как `(позиция + 4) & ~3`, а смещение литерала умножается на четыре. Адрес сопоставлен с известной загрузочной базой программы `0x06004000`, предварительно установленной на Stage 15.

В оригинальном `0TH2.BIN` найдена **одна** полная связка: шесть мест вызова и одна целевая процедура из пяти инструкций. Статический список из шести мест не означает, что все они выполняются в одном проходе: Stage 28 показал две независимые проверки на специальное значение.

## 2. Арифметика функции

Последовательность SH-2:

1. `MULS.W R4,R5` — два знаковых 16-битных множителя, 32-битный результат в MACL.
2. `STS MACL,R0` — перенос результата в R0.
3. `SHLR8 R0` — логический сдвиг 32-битного результата вправо на восемь позиций.
4. `RTS` — возврат.
5. `EXTS.W R0,R0` — знаковое расширение низких 16 бит **в слоте задержки RTS**, поэтому является частью возвращаемого результата.

Итоговая функция с точными регистровыми правилами: `return sign16( ( (sign16(R4) * sign16(R5)) & 0xFFFFFFFF ) >> 8 )`.

Это соответствует арифметике с восемью дробными битами (**Q8.8**). Для отрицательных произведений логический SHLR8 и последующее EXTS.W дают результат с усечением до 16 бит. Например, `125 × 0.5 = 62` после целочисленного сдвига, а `-125 × 0.5 = -63` в этой процедуре.

## 3. Поля коэффициентов и особое значение

Для первой группы исходной структуры загружается знаковое слово из поля `+88` в R12, затем перед вызовом оно переносится в R5. Для второй группы аналогично используется поле `+90`. Ранее восстановленные проверки сравнивают каждое поле с числом `0x0100` (256) и при равенстве обходят свою группу вызовов.

Теперь это решение имеет арифметическое объяснение: **256 в Q8.8 означает множитель 1.0**. Для такого коэффициента функция возвращает исходное знаковое 16-битное значение (с учётом ширины регистра), поэтому вызов можно пропустить.

| Группа | Поле коэффициента | Вызовов в исполняемом коде | Условие пропуска |
|---|---|---:|---|
| Первые два поля результата | +88 | 2 | коэффициент = 256 |
| Следующие четыре поля результата | +90 | 4 | коэффициент = 256 |

**Важно:** приведённые смещения относятся к структуре в оперативной памяти, не к положениям игровых файлов на диске. Обнаружение Q8.8-преобразования не доказывает, какие именно игровые параметры масштабируются: это могут быть размеры, координаты или иные числа.

## 4. Реализация

- `tools/stage29_sh2_q8_converter.py`: метаданные о единственном целевом преобразователе, проверка инструкций, расположения функции и точная модель знакового Q8.8 умножения.
- `tests/test_stage29_sh2_q8_converter.py`: синтетические проверки всех пяти инструкций, загрузки адреса, шести точек вызова, двух источников коэффициента, 16-битной знаковой арифметики и граничных случаев.
- На приватном оригинальном ISO подтверждено: 1 целевая функция; 6 точек JSR; совпадают обе загрузки знаковых коэффициентов и финальный EXTS.W в слоте задержки RTS.
- README и дорожная карта обновлены. Публичный CI запускается без исходного ISO.

Семантику SH-2 MULS.W, STS, SHLR8 и EXTS.W сверяли с руководством Renesas SH-2E Software Manual (https://docs.alexrp.com/sh/sh2e.pdf).
