# The Story of Thor 2 — Stage 49: контракт приватной SH-2-трассы записи VDP1

Дата: 22 октября 2026 года.

## Исходная точка

Stage 48 завершил GitHub CI с 960/960 синтетических тестов. Оригинальный ISO MK-81302 доступен приватно, его контрольная сумма совпадает с ранее зафиксированной. Результаты этапов 45 и 46 дают одну конкретную функцию копирования команд в VRAM VDP1 и один распознанный управляющий вызов.

**Новой выполненной трассы Sega Saturn пока нет.** В этом PR реализован строгий *контракт проверки* событий от отладчика. Инструмент не запускает сам эмулятор, не извлекает из ISO графику и не объявляет неподтверждённый захват настоящим исполнением.

## Что проверяет Stage 49

Новый `tools/stage49_sh2_vdp1_trace_contract.py`:

1. Приватно извлекает `0TH2.BIN` из исходного ISO с помощью уже существующего загрузчика.
2. Находит единственную статическую пару — копировщик Stage 45 и шлюз Stage 46 — и вычисляет необходимые **точные PC для проверок**, не записывая их в публичный отчёт.
3. Принимает один нормализованный приватный журнал JSONL, где должны присутствовать в строгом порядке:
   - `gate` — инструкция проверки знакового флага и начального счётчика;
   - `jsr` — вызов копировщика с исходным R5;
   - восемь `store` на каждую 32-байтную команду (с реальным PC, физическим адресом назначения и записанным 32-битным значением);
   - `copy_rts` — выход копировщика с R5=0;
   - `submit_rts` — выход шлюза, когда флаг и счётчик обнулены.
4. Проверяет, что каждая из восьми инструкций `MOV.L` срабатывает в ожидаемом месте кода и в правильном порядке, а адрес назначения соответствует `0x25C00000 + index*8 + command_number*32 + word_number*4`.
5. Если доступен приватный поток исходных команд, сравнивает также все 32-битные значения в порядке big-endian. При отсутствии исходных байтов проверка данных помечается как **не проведённая**, а полный контракт никогда не считается выполненным.
6. Сверяет глобальный бюджет R5 с суммой количеств команд во входных дескрипторах, а также предусловие отрицательного флага и итоговый сброс.

Для нормализованного журнала на два дескриптора с одной командой каждый ожидается **20 событий**: два управляющих, 16 записей, два выхода. Не нужно добавлять в JSONL каждую промежуточную инструкцию SH-2; контракт проверяет только указанные роли.

## Приватный формат событий — синтетический пример

```jsonl
{"role":"gate","pc":100000000,"status":-1,"pending_count":1}
{"role":"jsr","pc":100000002,"r5":1}
{"role":"store","pc":100000004,"dest":633339904,"value":16909060}
```

Числа в примере *вымышлены*. Для полной проверки требуется ещё семь последовательных событий `store`, `copy_rts` и `submit_rts`. Реальные значения PC должны приходить из отладчика при исполнении, а не копироваться из этого примера. Сырой журнал включает приватные адреса и слова команд и **не должен публиковаться**.

Обязательные поля каждой роли:

| Роль | Поля |
|---|---|
| gate | role, pc, status, pending_count |
| jsr | role, pc, r5 |
| store | role, pc, dest, value |
| copy_rts | role, pc, r5 |
| submit_rts | role, pc, status, pending_count |

Поля `pc`, `dest` и `value` — беззнаковые 32-битные целые; `status` — знаковый байт; `pending_count` и `r5` — числа 0…65535. Максимальный размер журнала 16 МиБ; максимум 4096 команд (32768 событий записи). Ограничения введены валидатором для безопасного анализа и **не являются доказанными пределами игры**.

## Пример закрытого запуска

```sh
python tools/stage49_sh2_vdp1_trace_contract.py \
  --iso-private /private/The\ Story\ of\ Thor\ 2.iso \
  --manifest-private /private/thor49/capture.json \
  --trace-jsonl-private /private/thor49/sh2-events.jsonl \
  --source-commands-private /private/thor49/commands.bin \
  --output-private /private/thor49/stage49.private-trace-contract.json
```

Метаданные `capture.json` используют ту же схему, что и Stage 48. Выходной отчёт создаётся как новый файл с правами 0600 без перезаписи. В отчёте присутствуют только агрегаты совпадений/ошибок, нет самих PC, VRAM-адресов, значений записей или игровых ресурсов.

## Интерпретация результата

Даже при `full_offline_trace_contract_matches=true` инструмент свидетельствует лишь о внутренней согласованности **предоставленного** журнала с найденным на приватном оригинальном `0TH2.BIN` статическим путём. Флаг `emulator_trace_authenticity_verified` остаётся `false`. Для подтверждения реального исполнения необходим захват доверенным отладчиком эмулятора и фиксация происхождения исходного ISO, эмулятора, сценария запуска и снимков VRAM. Причинная связь с обработчиком №39 остаётся отдельным исследованием.

## Тесты и дальнейшая работа

Добавлено 40 синтетических тестов: положительные и отрицательные проверки PC, направления и значений VRAM-записей, регистра R5, флага, порядка ролей, пропущенных/лишних событий, файлового JSONL, граничных условий, необоснованных заявлений о реальном исполнении и недопустимой утечки исходных адресов.

Следующий этап — обеспечить безопасный захват событий в реальном Sega Saturn-эмуляторе по приватным PC Stage 45–46, получить оригинальные значения R4/R5 и снять до/после VRAM. После этого сверить одновременно результаты Stages 48 и 49. До фактического захвата подтверждать запуск ремейка или восстановленные спрайты нельзя.

## Дополнительная приватная сверка на оригинальном ISO (22.10.2026)

Проверен хранящийся вне GitHub оригинальный ISO с ранее зафиксированным SHA-256. При независимом проходе по распакованному в оперативную память файлу 0TH2.BIN длиной 535552 байта найдены **один** полный совпадающий копировщик Stage 45 и **один** полный управляющий шлюз Stage 46. Сформированы **12 различных статических ролей PC** (проверка шлюза, JSR, восемь инструкций MOV.L-записи, RTS копировщика и RTS шлюза); их точные значения не опубликованы.

**Ограничение:** преобразование смещения файла 0TH2.BIN в PC использует статически выведенную гипотезу базы загрузки SH-2 `0x06004000`. Исполнение по этим PC ещё не наблюдалось, а реальный адрес загрузки не подтверждён дампом исполняющего эмулятора. Статическая уникальность пары функций и ролей не удостоверяет подлинность будущего журнала или вызов во время игры.
