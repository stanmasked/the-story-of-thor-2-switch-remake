# The Story of Thor 2 — Stage 102: сопоставление call-site с публичным SGL-примером

## Источники и метод

Продолжен локальный анализ исходного ISO без изменения файла. В качестве независимого внешнего ориентира изучен публичный разбор объектного кода Sega Graphics Library (SGL), функция `_slInitSystem`, опубликованный на SegaXtreme: https://segaxtreme.net/threads/converting-sgl-from-coff-to-elf/ . Это пользовательский разбор, а не официальная спецификация; он используется только как сопоставительный пример.

Внешний пример показывает вызов через низкоадресный function-pointer slot: код загружает адрес slot, читает хранящийся там указатель, выполняет косвенный `JSR` и передаёт аргументы через `R4`/`R5`, включая установку нуля в delay slot вызова. Анализатор Stage 102 проверяет только агрегированные формы аргументных регистров вокруг уже найденных call patterns; он не пытается восстановить runtime-адрес функции.

## Результат по игровому образу

- В root payloads повторно распознано 10 slot-dereference call patterns: шесть в `0TH2.BIN` и четыре в `SET07.BIN`.
- Шесть из десяти call patterns имеют подготовку аргумента в `R4` поблизости от вызова и `R5 = 0` в delay slot. Это совпадает с характерным соглашением аргументов в публичном SGL-примере.
- Четыре остальных call patterns используют immediate-подготовку `R4` в delay slot. Их точная семантика по одному только шаблону не устанавливается.
- В ранее ограниченном boot-code window сохраняется ещё один slot-call pattern.

## Интерпретация

Сочетание повторного использования одного slot в игровых модулях и сходного вызовного шаблона в публичном SGL-разборе усиливает гипотезу о resident SGL/service interface. Это больше, чем одно лишь общее ABI-ожидание, но не идентифицирует фактическую функцию, хранящуюся в slot. Публичный пример может относиться к другой сборке SGL; runtime-значение slot в нашем запуске неизвестно.

Поэтому вывод Stage 99 не меняется: `R13 = 1` во второй записи control byte остаётся условным, пока не подтверждено, что динамический callee сохраняет `R13` и loader-wrapper возвращается по нормальному успешному пути. Статический call-pattern match не доказывает runtime-вызов, runtime target или фактический выбор ветви.

## Реализация и тесты

Добавлен `tools/stage102_sgl_call_pattern_correlation.py`. Он повторно распознаёт существующие slot-call patterns и выдаёт только агрегированные количества по модулям и типам подготовки `R4`/`R5`. Отчёт не содержит RAM-адресов, смещений инструкций, исходных байтов, дампов или игровых payloads.

Добавлено шесть синтетических тестов: SGL-подобная форма `R4` плюс нулевой `R5` в delay slot, immediate-аргумент в delay slot, распознавание косвенного вызова, потеря происхождения после перезаписи target-регистра, агрегированные счётчики без местоположений вызовов и исключение постороннего регистра delay slot.
