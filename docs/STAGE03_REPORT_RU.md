# The Story of Thor 2 Remake — Stage 03: counted BE16 indexes

Дата исследования: **21 октября 2026**. Использован приватный образ `The Story of Thor 2.iso` (Sega Saturn, `MK-81302`). ISO и оригинальные файлы игры не загружались в GitHub.

## Что удалось подтвердить

Для **12 ранее выявленных трёхсекционных контейнеров** проверена гипотеза индексной таблицы:

- Заголовок секции начинается с числа `N` в формате **big-endian uint16**.
- Следом идут `N+1` 16-битных позиций. Первый действительный адрес совпадает с длиной префикса, `2 + 2*(N+1)`.
- Позиции находятся внутри секции и кратны двум. После исключения отсутствующих записей наблюдается неубывающая последовательность.
- Значения `0` и `0xFFFF` выступают кандидатами на маркеры отсутствующих записей.
- В **девяти вторых секциях** все действительные позиции последовательных записей разделены **6 байтами**, и после последней позиции до конца секции остаётся **6 байт**.

Результат: **21** таблица, удовлетворяющая указанным условиям; **9** кандидатов на непрерывные массивы шестибайтовых записей.

### Вывод

Модель индексов одинаково объясняет структуру некоторых контейнеров духов и файлов группы P. Разделение на таблицу переменной длины, таблицу шестибайтовых записей и крупный третий блок перспективно для дальнейшего **сопоставления графики, кадров анимации и управляющих данных**.

Но мы пока **не доказали**, что конкретная шестибайтовая запись — кадр анимации, координата спрайта или игровой объект. Нельзя считать эти системы восстановленными.

## Воспроизведение

Для приватного локального ISO, без публикации исходных данных:

```bash
python -m unittest discover -s tests -v
python tools/stage03_index_tables.py "/private/The Story of Thor 2.iso" -o stage03.json
```

Локальная проверка: **19/19 синтетических тестов** (8 Stage02 + 11 Stage03). Python CI проверяет только эти искусственные данные. Артефакт отчёта — структурные агрегаты без игровых бинарных данных.

## Что дальше (Stage 04 — назначение записей)

1. Проверить 6-байтовые записи относительно ожидаемых коротких полей (SH-2 BE16, фиксированные смещения), без преждевременной маркировки как «анимации».
2. Исследовать свойства третьей секции, включая выравнивание, локальные индексы, сигнатуры сжатия.
3. Сопоставить файлы персонажей и духов на уровне формата, затем проверить результат визуально в приватном эмуляторе Saturn.
4. Изучить `MAP.BIN`, `CHR.BIN`, `BGM.BIN`, `SET00.BIN`–`SET07.BIN` как отдельные форматы.
5. Только после достоверного восстановления структуры игровых данных создавать первые оригинальные игровые системы на C++/SDL2, а затем собирать NRO через devkitPro.

**Статус:** игры, нативного движка и Switch-билда пока нет. Рабочий результат — диагностические инструменты и проверяемая гипотеза внутреннего формата ресурсов.
