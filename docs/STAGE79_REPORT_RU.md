# The Story of Thor 2 — Stage 79: расширенная проверка SH-2 записей в поле длины

## Результат проверки оригинального образа

Файл `The Story of Thor 2.iso` найден в приватной папке проекта Google Drive и прочитан локально. Образ и извлечённый исполняемый файл не загружались в GitHub. Анализатор Stage79 был запущен локально на `0TH2.BIN`; опубликована только агрегированная сводка.

- Найдено **24** PC-relative literal-load-кандидата, указывающих вблизи исследуемого поля.
- Найдены **2** записи, чья вычисленная эффективная адресация совпадает с целевым 16-битным полем.
- Обе распознанные записи используют прямой режим `MOV.W Rm,@Rn`.
- В этих ограниченных окнах не найдено дополнительных записей через `ADD #imm` или копирование адреса в другой регистр.
- Не обнаружено распознанных store-кандидатов с неизвестным индексом `R0`.

Это совпадает с двумя писателями, уже выявленными Stage75/78. Расширение набора режимов адресации не обнаружило нового статического писателя в пределах применённого поиска.

## Что проверяет новый анализатор

`tools/stage79_expanded_store_alias_audit.py` расширяет поиск Stage78 и распознаёт:

- прямые записи байта, слова и длинного слова через `@Rn`;
- записи через `@-Rn` с учётом размера и изменения указателя;
- индексированные записи через `@(R0,Rn)`;
- записи слова/длинного слова с displacement;
- локальную адресную арифметику `ADD #imm,Rn` и копирование указателя `MOV Rm,Rn`;
- запись в delay slot распознанного перехода.

Добавлено десять синтетических тестов, включая каждый поддерживаемый режим, адресный алиас, перезапись регистра-указателя и проверку отсутствия приватных адресов в выходном JSON. Все десять тестов прошли в локальном окружении. Проверка GitHub Actions для PR выполняется отдельно.

## Границы доказательства

Этот поиск линейный и ограничен окном инструкций после PC-relative загрузки. Он не покрывает все варианты SH-2 арифметики, таблицы указателей в RAM, произвольные вычисляемые адреса, межпроцедурные изменения указателей и альтернативные входы в середину кода. Поэтому два найденных store-кандидата **не доказывают**, что в программе отсутствуют другие писатели.

По-прежнему не доказаны:
- инициализация поля длины до первого чтения;
- глобальная верхняя граница длины передачи;
- фактический порядок runtime-вызовов callback и submit gate;
- завершение SCU DMA и синхронизация с тем же кадром VDP1.

## Следующий этап — Stage80

1. Проверить инициализацию поля на уровне вызывающих функций и достижимого control flow, не выводя порядок выполнения из соседства инструкций в файле.
2. Расширить поиск источников адресов через сохранённые регистры, таблицы указателей и вызовы системного runtime.
3. Сопоставить найденные пути с настройкой D0MD и эффективными адресами D0R/D0W/D0C.
4. Не объявлять глобальный предел длины или runtime-завершение DMA без полной цепочки доказательств либо допустимой runtime-трассы.

**Статус:** Stage79 расширенный локальный поиск выполнен; новые писатели не обнаружены в пределах его модели. Полная доказанность инварианта длины и работающий ремейк для Nintendo Switch остаются отдельными незакрытыми задачами.
