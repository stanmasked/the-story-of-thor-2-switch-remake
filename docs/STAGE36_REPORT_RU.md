# The Story of Thor 2 — Stage 36: индексированная косвенная диспетчеризация таблицы SH-2

Дата: 22.10.2026. Приватно проверен оригинальный Sega Saturn ISO MK-81302, SHA-256 `25b0b2774d4621bd9f95a01fc5420ded37b481b61b3cdf515360d82b2cb7bb0d`. Исходный образ и ресурсы не опубликованы.

## Что установлено

Stage 35 связал 68-элементную таблицу адресов функций (выбранная ранее внешняя функция — элемент №39) с BRA-переходом в особую обёртку. Stage 36 нашёл **две полные независимые SH-2-последовательности**, которые выбирают адрес функции из этой таблицы.

Каждая последовательность выполняет:

1. `MOV #126,R0`, затем **знаковую 16-битную** загрузку `MOV.W @(R0,R14),Rn` из `[R14+126]`.
2. `SHLL2 Rn`: сдвиг индекса на 2, адресный шаг 4 байта.
3. `MOV.L @(disp,PC),R0`: получает 32-битную базу таблицы из PC-относительного литерала с 4-байтовым выравниванием.
4. `MOV.L @(R0,Rn),Rm`: считывает адрес целевой функции.
5. `JMP @Rm`: выполняет косвенную передачу управления; восстановление `R14` производится в слоте задержки JMP.

Отличия двух подтверждённых маршрутов:

| Признак | От начала таблицы | От элемента №39 |
|---|---|---|
| Исходный адрес | первый элемент | 39-й элемент |
| Индекс в программе | знаковое слово `[R14+126]` | знаковое слово `[R14+126]` |
| Регистры для индекса/цели | R2 / R3 | R3 / R2 |
| Восстановление перед JMP | непосредственно JMP | сначала R12 и R13, затем JMP |
| Слот задержки JMP | восстановление R14 | восстановление R14 |
| Значение индекса для внешней функции №39 | **38** | **0** |

## Математические границы — не проверенные игровые условия

В непрерывной таблице 68 адресов с нумерацией 0…67 чтение остаётся внутри этого массива при таких индексах:

- От начала таблицы: `0…67`.
- От адреса элемента №39 (нулевой индекс 38): `−38…29`.

Учитывается знаковая 16-битная интерпретация числа: например, `0xFFFF` — это индекс −1. Внутри двух подтверждённых суффиксов `MOV.W → SHLL2 → MOV.L → JMP` **не обнаружена локальная проверка границ**. Однако до попадания в эти суффиксы игра может проверять индекс; полный CFG и реальные значения отсутствуют. Поэтому нельзя утверждать, что в игре вообще нет защиты от выхода за границы.

## Проверка

- `tools/stage36_dispatch_index_audit.py` повторно находит таблицу Stage 35 и сверяет обе последовательности, включая PC-относительный адрес, ширину знакового индекса, восстановление регистров и слот задержки JMP. Вывод содержит только агрегированные сведения.
- `tests/test_stage36_dispatch_index_audit.py` — 30 синтетических тестов (положительные и испорченные SH-2-фрагменты, ширина чтения, выравнивание, JMP, задержка, индексные диапазоны, отсутствие исходных позиций в отчёте).
- Локальная проверка на оригинальном ISO: два совпадения, по одному для каждой формы, таблица из 68 записей, внешний элемент №39. Локальные синтетические тесты: 30/30; Stage 35 и Stage 36 вместе: 59/59.

Это **статическое восстановление механизма**, а не наблюдение выбора функции №39 во время прохождения игры. Не подтверждены конкретные значения `[R14+126]` в игровых кадрах, гарантии достижимости каждой ветки, входные объекты `R14`, графический формат, спрайты и запись в командный буфер VDP1.
