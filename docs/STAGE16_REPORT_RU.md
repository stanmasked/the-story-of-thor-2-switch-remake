# The Story of Thor 2 — Stage 16: найден производитель дескрипторов VDP1

Дата: 21.10.2026. Анализ выполнен локально на приватном ISO Sega Saturn MK-81302. В публичный репозиторий добавлены анализатор, синтетические тесты и агрегированные выводы; исходный ISO и игровые ресурсы не публикуются.

## 1. Найден путь записи в staging-буфер

В 0TH2.BIN обнаружен согласованный набор инструкций, который проверяет общий счётчик, получает текущий указатель буфера, записывает поля дескриптора, увеличивает счётчик и продвигает указатель.

| Проверка | Результат |
|---|---:|
| Кандидатов на запись полного дескриптора | 1 |
| Максимальная ёмкость по защитной проверке | 512 записей |
| Размер дескриптора | 8 байт |
| Смещения полей | 0, 4, 6 |
| Приращение указателя | 8 байт |
| Приращение общего счётчика на запись | 1 |

## 2. Поля дескриптора

- Смещение +0: 32-битный адрес источника. Он вычисляется как базовый адрес таблицы плюс индекс, умноженный на 8.
- Смещение +4: 16-битный курсор назначения.
- Смещение +6: 16-битное количество 32-байтовых записей для текущего источника. В найденном пути значение вычисляется как входной аргумент, сдвинутый вправо на три бита.

Это связывает Stage 15 с кодом, который действительно формирует записи для загрузчика. При этом адрес источника пока не сопоставлен с конкретным контейнером P0–P3, а семантика курсора назначения не подтверждена.

## 3. Важная открытая проверка

Производитель увеличивает общий счётчик на единицу при записи каждого дескриптора, но поле количества копий рассчитывает из аргумента, делённого на восемь. Загрузчик из Stage 15 уменьшает общий бюджет на каждый скопированный 32-байтовый блок.

Эти правила согласуются, если в этом пути каждый дескриптор представляет одну копию. Пока это не доказано: необходимо проследить вызывающие стороны и выяснить, может ли аргумент быть больше восьми либо существуют дополнительные пути учёта. Это открытый вопрос для следующего этапа, а не утверждение об ошибке оригинальной игры.

## 5. Следующий этап

Stage 17 — проследить вызывающие стороны функции-производителя и проверить входной аргумент. Нужно установить, всегда ли он соответствует одной 32-байтовой записи, найти другие места изменения общего счётчика и только после этого переходить к декодированию исходных ресурсов.

Статус: найден кандидат на реальный путь записи 8-байтовых дескрипторов в staging-буфер с защитой ёмкости 512 записей. Фактическое содержимое буфера, декодер текстур, игровой движок и Switch NRO ещё не созданы.
