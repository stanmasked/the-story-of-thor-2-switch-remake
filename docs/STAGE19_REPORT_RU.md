# The Story of Thor 2 — Stage 19: происхождение аргумента количества копий VDP1

Дата: 21.10.2026. Анализ настоящего приватного ISO Sega Saturn MK-81302 (SHA-256 `25b0b2774d4621bd9f95a01fc5420ded37b481b61b3cdf515360d82b2cb7bb0d`). Оригинальный ISO, исполняемые байты, точные смещения и игровые ресурсы в GitHub не публикуются.

## Обнаруженная статическая цепочка

В `0TH2.BIN` найден один блок, соответствующий строгой сигнатуре Stage 18 и дополнительной проверке Stage 19:

1. `CMP/EQ #1,R0` задаёт условие входа в ветку записи.
2. `BF/S` направляет исполнение в общий выход, если сравнение ложно. **Delay slot выполняется при обоих исходах.**
3. `EXTU.W R5,R4` в delay slot сохраняет младшие 16 бит регистра R5.
4. Внутри блока `MOV R4,R2`, три инструкции `SHLR R2`, затем `MOV.W R2,@R3` формируют 16-битное поле числа записей для источника.
5. Проверка ёмкости запрещает запись очередного дескриптора, если общий счётчик достиг 512.

Предварительно доказанная **локальная арифметика**:

```text
source_count = (R5 & 0xFFFF) >> 3
writer_entry_condition = (R0 == 1) and (descriptor_count < 512)
```

Теоретический диапазон `source_count` по этой арифметике — от 0 до 8191 включительно. **Это не измеренный диапазон значений во время игры.** Неизвестно, какие R5 реально допустимы на входе более широкой процедуры.

## Количественная проверка

| Признак | Результат |
|---|---:|
| Блоков записи Stage 18 на оригинальном ISO | 1 |
| Блоков с полным путём R5 → R4 → R2 → сдвиги → запись | 1 |
| Блоков с CMP/EQ и общим условным выходом | 1 |
| Блоков с EXTU.W в слоте задержки BF/S | 1 |
| Блоков с тремя SHLR до записи счётчика | 1 |
| Новых синтетических тестов | 12 |

Новый инструмент: `tools/stage19_writer_argument_flow.py`; его тесты — `tests/test_stage19_writer_argument_flow.py`. Локально пройдены 12/12 тестов и проверка на настоящем ISO. GitHub Actions запускает полную синтетическую коллекцию без образа игры.

## Открытые вопросы

- Откуда поступают R0 и R5 и какие их значения достижимы реально?
- Ограничивает ли окружающая процедура значение до одного 32-байтового блока на дескриптор? Пока **не доказано**.
- Почему производитель увеличивает общий счётчик на один дескриптор, а VDP1-загрузчик уменьшает счётчик на каждую копию? Может существовать иная семантика счётчика или дополнительный путь учёта, но это нужно подтвердить в исполнении.
- Куда в реальности указывают адреса источника и как они связаны с P0–P3?

Следующий приоритет: восстановить вызовы окружающей процедуры и путь формирования R5; затем проверить значения при запуске в эмуляторе. Наличие формулы не означает, что получен графический декодер или запускаемая Switch NRO.
