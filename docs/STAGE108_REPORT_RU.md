# The Story of Thor 2 — Stage 108: независимое сопоставление системного service-slot

## Подтверждённый результат

Сохранённый приватный оригинальный ISO (106954752 байт) и официальная европейская BIOS (524288 байт) повторно проверены по строгим SHA-256. Приватное входное значение slot, ранее полученное на оригинальном диске Stage100 и использованное в подлинном раннем SH-2 breakpoint Stage107, совпало с адресом, **опубликованным независимо от нашего проекта** в Saturn SH-2 ассемблерном примере для вызова изменения маски прерываний SCU.

Публичный пример показывает форму `MOV.L slot-pointer → MOV.L @pointer → JSR @callee` и помечает эту процедуру как работу с `SYS_CHGSCUIM`. Официальное Saturn System Program User's Manual отдельно определяет `SYS_CHGSCUIM(AndMask, OrMask)` и её назначение.

**Вывод:** гипотеза Stage103 о семантике *системной ячейки диспетчеризации* получила независимое публичное подтверждение; это весомее прежнего совпадения только по форме аргументов.

**Но это не устанавливает** конкретную цель указателя в работающей европейской BIOS, её реальный вход и возврат и сохранение `R13` в исследуемом позднем пути Stage99. Никакая проверка адреса сама по себе не доказывает фактическое исполнение функции.

## Реализация

В `tools/stage108_service_slot_external_crosscheck.py` добавлен fail-closed приватный анализатор:
- проверяет неподменённый оригинальный ISO и конкретную европейскую BIOS по точным размерам и SHA-256;
- принимает восьмизначный приватный адрес системной ячейки только в локальном файле;
- сравнивает его с публичной константой из независимого Saturn-примера;
- выводит исключительно безопасные булевы показатели и публичные ссылки, не раскрывая значения регистров, приватные адреса или байты исходных образов;
- всегда оставляет фактический вызов, сохранение `R13`, переход к позднему writer и gameplay неподтверждёнными.

Девять синтетических тестов локально прошли. Отдельно выполнен анализ на реальных приватных ISO, BIOS и Stage107 slot-input. Его JSON и SHA256-манифест должны сохраняться только в приватном Project Evidence Archive.

## Ограничение нового runtime-сбора

Дополнительные частные попытки автоматизировать Mednafen Read Breakpoints подтвердили, что точное значение системной ячейки вводится корректно, но в этих повторениях debugger был вооружён **после** требуемого раннего обращения. Полученные поздние кадры относятся к другим участкам BIOS/игры и **не являются** доказательством выполнения искомого `JSR`. Одна попытка reset также не дала однозначного искомого события. Нельзя смешивать их с ранее подтверждённой Stage107 остановкой.

Следующий этап: привязать ранний PC-breakpoint до загрузки game code либо добавить приватный программный SH-2 observer, затем собрать два независимых события `slot-read → JSR-entry → JSR-return` с `R13` до и после. Для позднего Stage99 writer потребуется отдельное свидетельство достижения. Данные приватных попыток/прошивка/образ — только в Google Drive, а не GitHub.
