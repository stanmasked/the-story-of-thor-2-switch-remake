# The Story of Thor 2 — Stage 50: проверка карты загрузки кода SH-2

Дата: 22.10.2026.

## Задача этапа

На Stage 49 подготовлены 12 ориентиров PC, связанных с одним статически распознанным шлюзом отправки VDP1 (Stage 46) и копировщиком 32-байтных команд (Stage 45). Предполагалось, что исходный код `0TH2.BIN` загружается в High Work RAM Sega Saturn с базы `0x06004000`. Для живой трассировки эту гипотезу требуется проверить по памяти работающего Saturn-эмулятора.

В доступном окружении эмулятор Saturn **не установлен** и его RAM-снимок **не получен**. Поэтому Stage 50 создаёт ограниченный, проверяемый инструмент для *будущего приватного снимка*, не объявляя факт настоящего исполнения.

## Что реализовано

Новый `tools/stage50_sh2_load_mapping_evidence.py`:

- Проверяет SHA-256 приватного ISO по **точной** ранее подтверждённой контрольной сумме MK-81302: `25b0b2774d4621bd9f95a01fc5420ded37b481b61b3cdf515360d82b2cb7bb0d`.
- Извлекает оригинальный `0TH2.BIN` приватно посредством `iso_file_payload` и повторно находит единственную пару Stage 45 / Stage 46.
- Строит 12 приватных образцов по 12 байт из инструкций у контрольных ролей PC: проверка флага, JSR, восемь 32-битных записей, RTS копировщика и RTS шлюза. Смещения и машинные байты остаются в оперативной памяти и никогда не экспортируются.
- В режиме без дампа выводит только *статический preflight*: сколько ролей найдено, сколько различных образцов удалось построить и что runtime подтверждения **нет**.
- С полным **приватным** 1-МиБ снимком High Work RAM `0x06000000…0x060FFFFF` проверяет совпадение всех 12 ролей при гипотетической базе кода `0x06004000` и независимо ищет другие полные размещения образцов в том же снимке.
- В случае только частичного совпадения или нескольких полных размещений **не утверждает однозначное соответствие** предполагаемой базе.
- Никогда не выставляет `emulator_origin_authenticated` или `actual_sh2_execution_observed` в `true`. Совпадение образца RAM может происходить без запуска игры: файл можно просто скопировать в память.

Обратите внимание: 12 образцов принадлежат всего **двум статически связанным участкам кода** и частично пересекаются. Число 12 — количество контрольных ролей, а не число независимых доказательств происхождения снимка.

## Приватная независимая сверка подлинного ISO

Дополнительно выполнена **реальная локальная статическая проверка** оригинального образа, без эмулятора. Контрольная сумма совпала с закреплённым SHA-256. Из корневого каталога ISO9660 считан `0TH2.BIN` объёмом **535552 байта**.

Независимый скан SH-2 подтвердил: **один** полный копировщик Stage 45, **один** управляющий шлюз Stage 46 и **12 различных контрольных позиций**, для которых получилось **12 различных 12-байтных образцов**. В публичный отчёт не включены точные PC, файловые смещения, исходные байты образцов и защищённые ресурсы.

Это подтверждает, что подготовленные ориентиры можно вычислить на оригинальном исполняемом файле. Снимка RAM работающего эмулятора не было, поэтому **не подтверждены ни загрузка кода по предполагаемой базе, ни выполнение инструкций игры**. В отчёте программы совпадение байтов предоставленного снимка теперь явно маркируется как недоверенное.

## Приватные команды

Только статическая проверка исходного ISO (применима уже сейчас):

```sh
python tools/stage50_sh2_load_mapping_evidence.py \
  --iso-private "/private/The Story of Thor 2.iso" \
  --output-private /private/thor50/static.private-load-map.json
```

Если и только если получен **реальный**, целиком считанный из High Work RAM снимок работающего Saturn-эмулятора (не произвольный .bin из ISO):

```sh
python tools/stage50_sh2_load_mapping_evidence.py \
  --iso-private "/private/The Story of Thor 2.iso" \
  --high-work-ram-private /private/thor50/high-work-ram.private-snapshot \
  --output-private /private/thor50/ram.private-load-map.json
```

RAM-файл обязан содержать ровно **1048576 байт** в порядке адресов High Work RAM, начиная с `0x06000000`. Отчёт метаданных создаётся как **новый** файл с правами 0600; не перезаписывает существующий файл. Нельзя помещать настоящий дамп RAM, VDP1 VRAM, BIOS, ISO или необработанный журнал PC/регистров в публичный репозиторий.

## Тесты

`tests/test_stage50_sh2_load_mapping_evidence.py`: 28 синтетических проверок для размещения по правильной базе, полной релокации, двух дублированных копий, частично изменённого кода, короткого/длинного файла, отказа от заявлений о реальном исполнении, утечки PC и проверки закреплённого ISO SHA. В CI используются только сгенерированные тестовые байты.

## Что остаётся

1. Получить подлинный снимок High Work RAM в работающем эмуляторе Saturn и подтвердить фактическую базу загрузки.
2. Отдельно зафиксировать происхождение снимка (название/версия/сборка эмулятора, контрольные суммы BIOS и ISO, событие игры).
3. После подтверждения карты SH-2 собрать настоящие событийные PC-логи по Stage 49 и снимки VDP1 до/после по Stage 48.
4. Только после сопоставления всех независимых данных исследовать связь с обработчиком №39 и действительные источники спрайтов.

**Stage 50 не создаёт игру и не подтверждает её запуск**. Он устраняет ещё одну непроверенную предпосылку для будущего захвата.
