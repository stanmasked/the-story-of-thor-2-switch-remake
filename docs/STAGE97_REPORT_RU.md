# The Story of Thor 2 — Stage 97: происхождение optional targets и достижимость CFG

## Источник и приватность

Оригинальный `The Story of Thor 2.iso` прочитан локально из Google Drive. В корневом каталоге найдено 33 файла: 30 payload размером до 5 MiB просканированы полностью, три больших CPK-контейнера исключены из полного code scan. ISO, игровые данные, адреса RAM, смещения инструкций и байты кода в репозиторий не добавлялись.

## Главное исправление анализа

Первый проход, начинавшийся только от общего stack-prologue, видел по одной literal-backed ссылке на каждую optional target в `0TH2.BIN`, но не находил их достижимыми. Это было ограничением выбора точки входа, а не доказательством мёртвого кода: общий error-helper начинается с участка, который не соответствует сигнатуре стандартного пролога.

Добавлен явный entry-anchor, выведенный из уже подтверждённой структуры loader-wrapper: уникальная общая цель wrapper-а, распознанные отрицательные ветви с кодами ошибок и их общий BSR. CFG начинается от найденного entry error-helper-а и заканчивается перед его pointer pool, чтобы данные таблицы не декодировались как инструкции.

## Результаты оригинального ISO

- Entry-anchor error-helper-а найден и прошёл проверки сигнатуры wrapper-а и общего error target.
- Optional target 1: одна literal-backed ссылка в `0TH2.BIN`; она лежит в явном entry-anchor окне, достижима по delay-aware CFG и за ней распознаётся `JSR @R0`.
- Optional target 2: одна literal-backed ссылка в `0TH2.BIN`; она также достижима по delay-aware CFG и за ней распознаётся `JSR @R0`.
- Для каждой цели найдена одна reachable indirect-call candidate; других literal-backed ссылок на эти значения среди 30 полностью просканированных корневых payload не найдено.
- Эти два вызова являются альтернативными достижимыми ветвями общего error-helper-а. Результат не означает, что обе функции вызываются за один проход или что какая-либо ветвь выполняется в runtime.

## Сопоставление с TH2.LOW

Повторная проверка loader destination обнаружила одну строку `TH2.LOW`, один literal-backed load-call candidate и один destination-base candidate; база уникальна в пределах этой эвристики. При таком сопоставлении обе optional target попадают внутрь `TH2.LOW` и выровнены по halfword.

- Optional target 1 совпадает с полным кандидатом общего stack-prologue в `TH2.LOW`.
- Optional target 2 не совпадает с полным generic-prologue, но сохраняет более слабую прежнюю форму входа: `PUSH R14` и последующий `STS PR`. Поэтому точка входа второй функции подтверждена слабее, чем первой.

Это согласованность статического адресного сопоставления, а не независимое доказательство runtime address space или исполнения overlay.

## Реализация и проверки

Добавлен `tools/stage97_optional_target_provenance_cfg.py`. Анализатор учитывает delay slots, разделяет ссылки в стандартных prologue windows и ссылки в явно подтверждённом caller-derived entry window, а также распознаёт ограниченные непосредственные `JSR`/`JMP`-использования загруженного указателя. Выход остаётся агрегированным и не содержит адресов или смещений.

Добавлено 13 синтетических тестов: достижимый и недостижимый literal site, branch delay slot, копирование указателя между регистрами, clobber регистра, bounded function windows и проверка уникальности базы TH2.LOW. Соответствующие 13 локальных контрольных сценариев прошли в независимом harness. GitHub Actions для новой ветки ещё не подтвердил полный запуск; CI-успех не заявляется.

## Следующий этап — Stage 98

1. Исследовать вход второй optional target, для которой обнаружена только частичная prologue-сигнатура; найти дополнительные caller- или CFG-якоря.
2. Проследить чтение и записи глобального байта, который управляет условными ветвями error-helper-а, и определить условия выбора каждой ветви.
3. Проследить статические side effects и возвращаемые значения двух optional функций, не выводя семантику только из их расположения.
4. Сохранять различие между статической достижимостью и runtime-выполнением.

**Границы вывода:** обе optional target имеют по одному достижимому статическому indirect-call site из caller-anchored CFG error-helper-а; обе согласуются с кандидатным диапазоном TH2.LOW, но второй entry слабее подтверждён сигнатурно. Runtime-вызовы, точная семантика целей, callback/service-slot регистрация, overlay execution, DMA completion и same-frame graphics timing остаются неподтверждёнными.
