# The Story of Thor 2 — Stage 98: аудит записей управляющего байта

## Источник и приватность

Оригинальный `The Story of Thor 2.iso` проверен локально. В корневом каталоге найдено 33 файла; 30 payload до 5 MiB просканированы полностью, три больших CPK-контейнера пропущены при полном code scan. ISO, игровые данные, адреса RAM, смещения инструкций и байты кода не добавлялись в репозиторий.

## Результаты

- Общий error-helper и адрес его управляющего байта повторно извлечены через caller-derived anchor Stage 97.
- Найдено четыре точные literal-backed ссылки на этот байт, все в `0TH2.BIN`: две в функции инициализации и две в самом error-helper-е.
- Найдены ровно два кандидата записи по точному эффективному адресу; оба — однобайтные `MOV.B` в `0TH2.BIN`. Другие полностью просканированные root payload не содержат точных кандидатов записи.
- Найден достижимый из стартового кода literal-backed JSR на функцию инициализации. CFG от этой точки достигает обеих записей; обе встречаются только в delay slot вызова, поэтому линейный просмотр без семантики delay slot мог бы неверно классифицировать порядок исполнения.

## Что подтверждено для двух записей

### Первая запись

Первая запись выполняет `MOV.B` из `R14` в управляющий байт в delay slot косвенного JSR. В caller-функции `R14` перед этим устанавливается в ноль; между установкой и delay slot нет промежуточных вызовов или ветвлений, способных изменить источник. Значение `0` для первой записи подтверждено статическим анализом.

### Вторая запись

Вторая запись выполняет `MOV.B` из `R13` в тот же байт в delay slot BSR. `R13` устанавливается в `1` ранее в той же caller-функции; в линейном участке до второй записи нет явной инструкции, которая переопределяет `R13`. Однако до записи встречаются три вызова и условная ветвь. Поэтому конечное значение `R13` не объявляется доказанным: необходимо проверить сохранение регистра всеми промежуточными callees и их вложенными вызовами.

## Связь с ветвями error-helper-а

Обе ветви error-helper-а читают один и тот же байт. Если чтение даёт ноль, условная ветвь пропускает соответствующий optional indirect call; при ненулевом значении этот вызов становится достижимым. Это согласуется с инициализацией «сначала ноль, затем возможная запись ненулевого значения», но пока доказан только нулевой этап. Назначение двух optional функций и фактический runtime-выбор ветвей не установлены.

## Реализация и проверки

Добавлен `tools/stage98_control_byte_writer_audit.py`. Он извлекает адрес управляющего байта из уже распознанного error-helper-а, сканирует root payloads на pointer aliases и точные записи, затем требует достижимую caller-derived CFG-точку входа. Отчёт агрегированный и не выдаёт приватные адреса или смещения.

Добавлено шесть синтетических тестов для pointer-alias записи, caller-derived entry, достижимости delay slot, подтверждения нулевого источника и консервативной обработки источника после вызовов. Результаты GitHub Actions для Stage 98 будут зафиксированы отдельно; до завершения запуска CI-успех не заявляется.

## Следующий этап — Stage 99

1. Проверить три вызова между установкой `R13=1` и второй записью: два локальных target-а и вызов loader-wrapper-а.
2. Для каждого reachable callee проследить, сохраняет ли он `R13`, включая вложенные косвенные вызовы; отдельно отметить границы, где исходник callee отсутствует в исследуемых root payloads.
3. После этого подтвердить или отвергнуть значение второй записи `1`.
4. Затем уточнить, какие условия реально ведут к двум optional indirect calls; не приписывать им семантику callback или сообщения без независимых признаков.

**Границы вывода:** две статические записи управляющего байта найдены и достижимы из подтверждённой caller-derived CFG-точки; первая записывает ноль. Вторая использует `R13`, предварительно установленный в единицу, но его значение после промежуточных вызовов не доказано. Runtime-значение байта, фактическая загрузка, overlay execution, runtime-выбор ветвей, callback-регистрация, DMA completion и same-frame graphics timing остаются неподтверждёнными.
