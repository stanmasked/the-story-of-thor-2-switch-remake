# The Story of Thor 2 — Stage 71: цепочка регистрации и вызова callback ID 64

## Цель

Продолжить Stage 70 и проверить не только факт регистрации функции, записывающей отрицательный статус, но и статическую связь между:
1. регистрацией функции под ID 64;
2. таблицей 256 обёрток, выбираемых по знаковому 8-битному ID;
3. общей обёрткой ID 64;
4. таблицей callback-указателей, которую читает общий вызов;
5. косвенным вызовом зарегистрированной функции.

Оригинальный ISO был прочитан из приватного источника; извлечённый исполняемый файл использовался только локально. В репозиторий добавлены только анализатор, синтетические тесты и агрегированный отчёт.

## Результат статической проверки

На локальном 0TH2.BIN проверка подтвердила:

- найден ровно один submit gate, проверяющий общий статусный байт;
- найден один кандидат writer-а, записывающий в этот байт отрицательное значение;
- указатель writer-а передаётся диспетчеру регистрации с ID 64;
- диспетчер вычисляет индекс ID × 4, сохраняет callback-указатель в таблице и передаёт соответствующую обёртку внешнему регистратору, адрес которого берётся из изменяемого глобального слота;
- таблица содержит 256 указателей на шестибайтные обёртки. Все 256 записей соответствуют ожидаемому порядку знаковых 8-битных идентификаторов и ведут к общей обёртке вызова;
- запись ID 64 ведёт к обёртке, которая выбирает слот callback-таблицы по тому же индексу;
- общая обёртка читает callback-указатель из той же таблицы, проверяет его на ноль и только затем выполняет косвенный JSR.

Таким образом, теперь статически подтверждена полная цепочка **регистрация writer-а → ID 64 → обёртка ID 64 → чтение зарегистрированного callback-указателя → защищённый от нулевого указателя косвенный вызов**. Это более сильное доказательство, чем одна лишь запись callback-а в таблицу.

## Что это не доказывает

- Не доказано, что внешний регистратор действительно вызывает обёртку ID 64 во время игрового кадра.
- Не установлено, кто и когда устанавливает внешний указатель регистратора.
- Не получена runtime-трасса, подтверждающая, что writer переводит submit gate в разрешающее состояние именно перед конкретной отправкой VDP1.
- Не подтверждён порядок изменения FBCR и автоматического запуска рисования на границе кадра.

Следовательно, причинная связь на уровне статического кода прослежена до косвенного вызова, но **runtime-вызов и кадровая синхронизация остаются неподтверждёнными**.

## Изменения и тесты

Добавлен tools/stage71_callback_dispatch_chain.py. Он проверяет цепочку регистрации, всю 256-элементную таблицу обёрток, ID 64, совпадение callback-таблицы в регистрации и вызове, проверку нулевого указателя и косвенный вызов. В вывод попадают только агрегаты и логические признаки; приватные адреса, смещения, байты инструкций и содержимое оригинального образа не выводятся.

Добавлен tests/test_stage71_callback_dispatch_chain.py с шестью синтетическими сценариями:
- корректная цепочка регистрации и косвенного вызова;
- другой ID не считается ID 64;
- повреждённая запись обёртки ID 64;
- несовпадающая таблица в общей обёртке;
- отсутствие подтверждённого адреса статуса;
- отсутствие приватных адресов и позиций в отчёте.

Тесты используют только искусственные данные и не требуют ISO.

## Следующий этап

Stage 72 должен проследить происхождение внешнего регистратора: найти статические записи в его глобальный слот, определить вызываемые функции и установить, каким событием или циклом выбирается обёртка ID 64. Без достоверной runtime-трассы нельзя утверждать, что этот путь реально исполняется в нужный момент.

**Безопасность данных:** ISO, извлечённый 0TH2.BIN, сырые байты инструкций, приватные адреса, оригинальные ресурсы и runtime-дампы не включены в PR.
