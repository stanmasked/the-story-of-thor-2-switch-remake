# The Story of Thor 2 — Stage 53: приватная карта точек останова Mednafen

Дата: 22 октября 2026 года.

## Что фактически доступно

Проверенный приватный ISO игры The Story of Thor 2 (Saturn) имеет закреплённый SHA-256:

`25b0b2774d4621bd9f95a01fc5420ded37b481b61b3cdf515360d82b2cb7bb0d`

Статическая схема Stage51 подтвердила 1st READ ADDRESS = 0x06004000, а Stage45/46 — пару функций копирования 32-байтных команд и шлюза отправки VDP1. Stage48/49 исправлены после обнаружения различия между внутренним R2 (количество команд) и внешним R5 (количество дескрипторов).

В контейнере этого исследовательского запуска **нет установленного Mednafen, Yabause или другого Sega Saturn-эмулятора**. Сетевой установщик Debian недоступен. Ни один настоящий снимок High Work RAM / VDP1 или событий SH-2 пока не снят. Поэтому этот этап не заявляет пройденную игру или работоспособный Switch NRO.

## Что сделано

Добавлен `tools/stage53_mednafen_private_capture_plan.py`. Он принимает исключительно оригинальный приватный ISO с зафиксированным SHA-256, проверяет Stage51 boot layout, извлекает 0TH2.BIN **только в оперативную память** и собирает приватный локальный план захвата:

- 12 точных PC-ориентиров Stage49: проверка флага в шлюзе, JSR копировщика, восемь инструкций 32-битных записей в VDP1, RTS копировщика, RTS шлюза.
- Четыре глобальных адреса Stage46 для отслеживания флага, количества дескрипторов, указателя буфера и последнего отправленного указателя.
- Рецепты трёх выгрузок: High Work RAM ровно 1048576 байт, VDP1 VRAM before и after по 524288 байт.
- Последовательность действий оператора и исходные горячие клавиши официального отладчика Mednafen.

**Приватные адреса из оригинального кода сохраняются только в локальном выходном JSON**, создаваемом с правами 0600, без перезаписи и следования по уже существующему симлинку. Стандартный вывод программы содержит только безопасные агрегаты — сколько подготовлено ролей, диапазонов и адресов, а не сами значения.

Команда для закрытого рабочего окружения:

```sh
python tools/stage53_mednafen_private_capture_plan.py \
  --iso-private "/private/The Story of Thor 2.iso" \
  --output-private "/private/stage53/private-mednafen-watchlist.json"
```

**Важно:** файл `private-mednafen-watchlist.json` не публиковать, не передавать в общие логи и не добавлять в публичный Pull Request. Он содержит конкретные адреса и опорные данные из защищённого оригинального исполняемого кода.

## Подтверждённые действия в отладчике Mednafen

Официальная документация: https://mednafen.github.io/documentation/debugger.html

1. Открыть приватный диск и включить отладчик `ALT+D`.
2. Перейти к CPU debugger через `ALT+1`; установить PC breakpoints клавишей `Space` на выбранных инструкциях. Поиск точных PC производится **из локального приватного файла**, а не из этого публичного отчёта.
3. Открыть редактор памяти `ALT+3`, выбрать правильное адресное пространство `CTRL+Left/Right`, проверить его карту (CPU logical memory или соответствующий домен).
4. При нажатии `D` команда выгрузки памяти документирована в формате `start_address +count filename`. Предполагаемые CPU-адреса: `06000000 +100000 highram.private-snapshot` для High Work RAM; `25C00000 +80000 before.vram` и аналогичная после. **Не считать эти адреса доступными, пока не подтверждён соответствующий домен памяти в текущем Mednafen**.
5. Проверить реальные размеры: RAM 1048576 байт, VDP1 VRAM 524288 байт каждый. Не подменять RAM-файл содержимым 0TH2.BIN из ISO.
6. На PC-событиях зафиксировать значения флага, R2/R5, указателей, 32-битных записей и источников команд. По отдельности захватить приватный список 8-байтных дескрипторов.
7. После закрытого захвата подготовить Stage48/49 манифесты и, если доступны сопоставимые кадры/циклы, использовать интегральную проверку Stage52.

Ключевое ограничение: отладчик Mednafen документирует ручные breakpoint и memory dump, но **не документирует автоматический экспорт всего журнала инструкций с цикловыми метками**, ожидаемый Stage52. Этот дополнительный инструмент для трассировки потребует отдельной реализации или возможностей другого эмулятора. Ни один пользовательский скрипт нельзя объявлять настоящей трассировкой без данных реального исполнения.

## Тестирование и следующая задача

Добавлено 28 тестов исключительно с искусственным кодом SH-2: точность ролей и PC, неизменность порядка, сопоставление четырёх глобальных адресов, правильные объёмы выгрузок, отсутствие приватных PC в публичном отчёте, запрет перезаписи/симлинков и отказ на неправильном ISO.

Следующий этап — **практически запустить Sega Saturn в среде, где установлен отладчик**, проверить memory domain для RAM/VDP1, получить первый подлинный дамп High Work RAM, а затем конкретный PC/VDP1 trace. Stage53 сам этих действий не выполняет.
