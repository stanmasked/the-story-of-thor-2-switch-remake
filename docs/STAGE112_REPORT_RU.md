# The Story of Thor 2 — Stage 112: наблюдение живости и возврата SH-2

## Что подтверждено до этого этапа

Stage111 в двух приватных запусках оригинального ISO с проверенной европейской BIOS подтвердил изменение одного целевого байта high-WRAM из 0 в 1 при исходном R13=1. Микроархитектурная привязка к точной исполняемой инструкции, полный путь BSR/RTS и сохранение R13 **на всех путях** пока не доказаны.

## Проверенный реальный материал Stage110

Новый публичный fail-closed анализатор `stage112_bounded_sh2_liveness_audit.py` применяется только локально к 4096 полным парам сырых состояний. В проверенной исходной трассе сначала присутствует короткая переходная последовательность, затем наблюдается повторение четырёх значений RPC **1021 раз**. Регистр PR меняется в раннем фрагменте; изменения R13 в видимых pre-step состояниях нет. Эти данные устанавливают лишь **конечный наблюдаемый интервал**, а не выполнение RTS / возврат из подпрограммы. Поля RPC / PC_ID / PC_IF отражают конвейер SH-2 и сами по себе не указывают однозначно адрес выполняемого опкода.

## Stage112 — публичные инструментальные изменения

`stage112_patch_mednafen_event_monitor.py` добавляет к проверенному источнику Mednafen 1.29.0 третий, **выключенный по умолчанию** наблюдатель. Он включается лишь через явные переменные среды при приватном исполнении. Адрес запуска и указатель управляющего RAM-байта поступают извне, не хранятся в коде. В отсутствие этого режима на исполнение ничего не записывается. При включении с лимитом **не более 2 млн SH-2 шагов** монитор сохраняет только моменты изменений R13, PR и RAM-байта, редкие контрольные срезы и возможные совпадения RPC с PR, а не все повторяющиеся строки цикла. Максимум событий также ограничен. Для RAM используется физический массив WorkRAMH: MMIO не читается.

`stage112_event_log_gate.py` строго проверяет заголовок, шаги, структуру событий и сигнал достижения лимита, возвращая **только обезличенные количества и логические поля**. Признак совпадения RPC и PR именуется `rpc_equals_pr_candidate`: он *не* доказывает исполнение RTS или фактический возврат. При преждевременном завершении запись классифицируется как неполная.

CI собирает только публичный исходный Mednafen и пакует свободно распространяемую бинарную библиотеку FLAC, чтобы приватное восстановление не зависело от исчезающего `/lib` временной среды. Оригинальная игра, BIOS, данные памяти, приватные адреса и сырые трассы в публичные GitHub Actions никогда не передаются.

## Доказательная граница

Подтверждение полного BSR/RTS возможно лишь по самостоятельным runtime-свидетельствам о фактическом исполняемом опкоде, корректном стеке/PR и завершённом возврате. Даже положительный `rpc_equals_pr_candidate` недостаточен. Пока эти доказательства отсутствуют, Stage104 **остаётся условным**. Дополнительно нужны проверки альтернативных ветвей и отсутствия независимых писателей целевого байта.
