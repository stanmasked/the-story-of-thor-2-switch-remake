# The Story of Thor 2 — Stage 104: граница ABI-доказательства для R13

## Внешние контракты

Документация Sega для `SYS_CHGSCUIM(AndMask, OrMask)` определяет обновление маски SCU через AND/OR. Публичный разбор SGL `_slInitSystem` связывает похожий вызов через тот же тип pointer-slot с `SYS_CHGSCUIM`. Общие соглашения Hitachi SH C compiler ожидают сохранение регистров R8–R14 между обычными вызовами, хотя компилятор поддерживает специальные режимы и исключения для функций без стандартного save/restore.

## Объединённая статическая цепочка

Stage 99 установил, что источник второй записи управляющего байта — R13, заранее установленный в `1`; перед записью выполняются три вызова, а сама запись находится в delay slot следующего BSR. Один локальный callee явно сохраняет/восстанавливает R13. Loader-wrapper сохраняет R13 на нормальном успешном пути. Первый callee не содержит прямых записей R13, но использует динамический вызов через общий service slot.

Stage 103 показал, что все 11 call patterns через этот slot имеют пары аргументов, совместимые с `SYS_CHGSCUIM(AndMask, OrMask)`. Это делает `SYS_CHGSCUIM` высоковероятной статической гипотезой для slot target. Если эта гипотеза верна и фактическая BIOS-реализация следует обычному SHC calling convention, сохранение R13 ожидается, а вторая запись должна получать `1` при нормальном возврате wrapper-а.

## Результат evidence gate

Добавлен `tools/stage104_r13_abi_evidence_gate.py`, который объединяет только санитизированные aggregate JSON-отчёты Stage 99 и Stage 103. Он проверяет seed, три pre-store вызова, delay-slot позицию записи, отсутствие прямых записей R13 в первом callee, подтверждённый local BSR, успешный путь wrapper-а и совместимость аргументной формы с `SYS_CHGSCUIM`.

Gate намеренно различает три вывода:
- **Условный статический вывод поддержан:** при target = `SYS_CHGSCUIM` и соблюдении обычного SHC ABI значение R13 должно сохраняться, а источник второй записи остаётся `1`.
- **Конкретная BIOS-реализация не проверена:** сам BIOS-код отсутствует в игровом ISO, а подходящего BIOS/trace/capture в доступных приватных Drive/Library материалах не найдено.
- **Runtime-доказательства нет:** gate никогда не выставляет `runtime_r13_preservation_confirmed` или `unconditional_r13_one_proven` в `true`, даже если все статические условия выполнены.

Добавлено девять синтетических тестов, проверяющих, что условный вывод открывается только при полном наборе статических условий и никогда не превращается в безусловное/runtime-утверждение.

## Текущий вывод

С учётом Stage 103, исходная неопределённость Stage 99 существенно сужена: неизвестный вызов, вероятнее всего, является системной функцией `SYS_CHGSCUIM`, а не произвольным игровым callback. Поэтому сохранение R13 имеет сильную поддержку через ABI-контракт. Однако без проверки точной ROM-реализации или runtime-трассы это остаётся **условным выводом**, а не абсолютным доказательством.

**Граница доказательства:** ABI делает сохранение R13 ожидаемым для предполагаемой цели `SYS_CHGSCUIM`, но не подтверждает точный runtime target или поведение конкретной BIOS-ROM реализации.
