# The Story of Thor 2 — Stage 41: подтверждённые читатели общего пула 276-байтных объектов

Дата: 22.10.2026. Приватно проверен исходный Sega Saturn ISO MK-81302 (SHA-256 `25b0b2774d4621bd9f95a01fc5420ded37b481b61b3cdf515360d82b2cb7bb0d`). В публичный репозиторий не передаются ISO, оригинальный исполняемый код, позиции команд и графические или звуковые ресурсы.

## Исходный факт и метод

Stage 40 связал запись индекса 38 с созданием копии структуры длиной 276 байт. Копия размещается в пуле из максимум 43 слотов с шагом 276 байт. Stage 41 независимо извлекает адрес **того же самого пула** из PC-относительного литерала функции выделения слота, а затем ищет другие участки кода с согласованным указателем, обращениями к индексному полю +126 и шагом 276 байт.

Алгоритм требует не одного похожего opcode, а нескольких независимых признаков: `MOV.L` загружает адрес пула в R4, проверяется начальное 16-битное слово записи, выполняется `MOV #126,R0; MOV.W @(R0,R4),R0; CMP/EQ #value,R0`, и далее используется PC-относительный литерал 276 с `ADD` к R4. Без полного сочетания совпадение отклоняется.

## Подтверждённые значения на оригинальном 0TH2.BIN

| Показатель | Найдено |
|---|---:|
| Вместимость общего пула | **43 записи** |
| Размер записи / шаг | **276 байт** |
| PC-относительных загрузок адреса пула | **57** |
| Из них непосредственно в регистр R4 | **21** |
| Независимых читателей с проверкой первого слова, индекса +126 и шага 276 | **4** |
| Операций «прочитать индекс +126, сравнить константу» в этих читателях | **11** |
| Сравнений с индексом 4 | **1** |
| Сравнений с индексом 21 | **3** |
| Сравнений с индексом 36 | **7** |
| Сравнений с индексом 38 среди этих четырёх читателей | **0** |
| Других процедур поиска свободной записи того же пула | **1** |

В четырёх проверенных группах начальные слова записи сравниваются соответственно со значениями 46, 84, 52 и 52. Это могут быть признаки состояния/типа, но их игровая семантика пока неизвестна. Все четыре группы независимо используют именно тот адрес пула, который загружает функция выделения записи Stage 40.

### Дополнительная функция поиска свободного слота

В другом участке кода найдена отдельная SH-2-функция, которая загружает начало общего пула в R4, проверяет до **43** первых слов, переходит к следующему слоту на **276** байт, возвращает указатель на нулевую запись в R0, а при отсутствии свободной записи возвращает нуль. В отличие от выделителя Stage 40, исследуемая последовательность **не помечает найденную запись как занятую**. Это ещё одно подтверждение организации общего пула.

## Значение и пределы

Теперь статически подтверждено, что 276-байтные записи не являются только промежуточной копией внутри одной функции: несколько других участков кода адресуют тот же пул и читают поле +126 его записей. Однако нельзя утверждать, что все четыре конкретные группы выполняются над созданной на Stage 40 копией с индексом 38, или что сама эта копия достигает **68-элементной** таблицы обработчиков.

Отсутствие прямых сравнений с 38 в четырёх группах не означает отсутствия других потребителей: косвенный `JMP` через таблицу может использовать индекс без отдельного `CMP/EQ #38`.

Следовательно, Stage 41 **не объявляет подтверждёнными** исполнение игры, идентичность указателей на отдельные экземпляры, запись команд VDP1, формат пикселей, декодер спрайтов или Switch NRO.

## Код и проверки

- `tools/stage41_pool_readers.py` — заново устанавливает pool provenance через Stage 40, проверяет совместное чтение полей, шаг записей и отдельный поиск свободного слота; JSON содержит только агрегированные значения.
- `tests/test_stage41_pool_readers.py` — **39 синтетических тестов** для четырёх групп читателей, свободного сканера, повреждённых SH-2 инструкций, разных значений индексов, проверки независимости и защиты приватных смещений. Локально: 39/39.
