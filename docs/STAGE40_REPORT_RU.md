# The Story of Thor 2 — Stage 40: выбор слота и клонирование структуры перед записью индекса 38

Дата: 22.10.2026. Исследован исходный Sega Saturn ISO MK-81302, SHA-256 `25b0b2774d4621bd9f95a01fc5420ded37b481b61b3cdf515360d82b2cb7bb0d`. Оригинальный ISO, машинные байты исполняемого модуля, абсолютные положения функций и ресурсы остаются приватными.

## Итог Stage 40

Stage 39 установил, что процедура №78, выбираемая в одном из участков индексом 77, получает новый указатель через `R0 → R14` и записывает в `[R14+126]` индекс 38. Теперь прослежены **обе вспомогательные функции** по адресам, загружаемым из PC-относительных 32-битных литералов перед их `JSR`.

### Первая функция — выбор свободной записи

Её последовательность SH-2 загружает начало области записей через `MOV.L`, устанавливает счётчик `R6=43`, использует `MOV.W @R5,R3; TST R3,R3`, переход `BF` при занятой записи и шаг между записями, заданный 16-битным PC-относительным литералом **276 байт**.

При обнаружении нулевого слова в начале записи функция временно записывает туда **−1**, а в поле **+128** помещает полученное через `R4` слово (в исследованном месте вызова значение 240). Она возвращает указатель на выбранную запись в `R0` через слот задержки `RTS`. Когда счётчик записей исчерпан, возвращает `R0=0`.

Это **статическое описание процедуры выбора слота**, а не наблюдение её фактической загрузки или расходования всех 43 слотов в эмуляторе.

### Вторая функция — копирование 276 байт

После успешного получения ненулевого `R0` вызывающая функция сохраняет указатель в `R14`. Затем в слоте задержки `JSR` передаёт:

- `R4=R13`: исходный объект, полученный как аргумент выбранной процедуры;
- `R5=R14`: выбранную новую запись.

Установленная по SH-2 опкодам функция копирования начинает со счётчика **69 длинных слов**, передаёт данные из `MOV.L @R4+,R2` в `MOV.L R2,@R6`, продвигает указатель назначения на четыре байта и повторяет три такие записи за итерацию. Счётчик уменьшается на 3; переход `BF/S` возвращается к циклу до исчерпания 69 слов. Получается **23 итерации и 276 байт**. Последнее продвижение указателя выполняется в слоте задержки перехода.

| Обнаруженный параметр | Результат |
|---|---:|
| Максимальное количество проверяемых записей | **43** |
| Шаг области слотов | **276 байт** |
| Копируемых длинных слов | **69** |
| Размер копии | **276 байт** |
| Итераций по три слова | **23** |
| Начальная запись слова при выборе слота | смещение **+128** |
| Константа первого аргумента выбора слота | **240** |
| Индекс, записываемый в скопированный объект | **38** |

**Шаг выбора записи точно совпадает с размером копии.** Это важное независимое согласование двух функций: одна выделяет запись фиксированной длины, другая переносит в неё всю структуру той же длины.

### Что это меняет в понимании объектов

Теперь известен статический маршрут: **объект R13 → выбор свободной записи → копирование 276 байт в R14 → изменение байта R14+7 и слова R14+126 на 38**. Следовательно, код Stage 38 меняет отдельную копию, а не пишет слово непосредственно через исходный указатель `R13`.

Временная отметка −1 и запись поля +128 в свободном слоте могут быть перезаписаны полной копией, что соответствует изученному порядку вызовов. Смысл самих полей, назначение объекта в игре и его дальнейший жизненный цикл пока не доказаны.

## Проверки и реализация

- `tools/stage40_pool_clone_audit.py` проверяет полные SH-2 сигнатуры двух функций, оба PC-relative адреса, литералы 128/276, цикл 69 слов, путь `R0 → R14` и аргументы функции копирования. На выходе только обезличенная сводка.
- `tests/test_stage40_pool_clone_audit.py`: **38 полностью синтетических тестов** с положительными случаями, повреждением opcode/адресов/слотов задержки, проверкой ширины, копирования и границ. Локально: 38/38.
- В приватном оригинальном `0TH2.BIN` найдена **одна полная статическая связка** двух функций с процедурой, устанавливающей индекс 38.
